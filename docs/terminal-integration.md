# 外部终端与 cmux 集成

## 启动路径

Driver 提供选定的原生 CLI、会话编号、工作目录和配置目录。TerminalLauncher
创建一次性启动入口并取得会话写权，然后由终端适配器打开新窗口或工作区。
项目目录的普通终端不接管聊天会话。

选择 cmux 时，复用本机 cmux 安装包中的集成脚本，不分发或重写其钩子实现：

| Agent | 启动集成 |
| --- | --- |
| Claude Code | cmux-claude-wrapper |
| Codex | cmux-codex-wrapper |
| Hermes（HTTP / ACP） | cmux-hermes-agent-wrapper |
| Amp | cmux-amp-wrapper |
| 其他 Agent | 保留原生命令与终端环境；已有的原生钩子、插件或扩展继续由各自配置管理 |

若 cmux 或对应脚本不存在，保留普通 CLI 启动能力。使用 Terminal、iTerm2 时
不注入 cmux 脚本。用户在 cmux 中关闭的集成保持关闭。

原生参数保持不变，包含明确的会话编号，禁止按最新会话猜测绑定。
配置目录允许保存非敏感路径；认证信息从启动环境及原生配置获取，不复制进启动记录。
Claude 启动保留原有认证与供应商环境，避免包装脚本切换账号来源。

## 返回 Kaus

- **继续在终端**：关闭确认框，保留终端占用，Kaus 中可以查看记录。
- **结束终端并切回**：停止该次启动的 Agent 及同一进程组中的工具，确认退出后
  同步原生历史、释放写权并恢复 Kaus 输入。

停止操作检查进程所属用户、启动时间和独立进程组。先发终止信号，等待三秒，
仍未结束才强制停止。无法核实进程或停止失败时保留占用，不影响其他终端会话。
原生 CLI 自行退出也走同一交接流程；历史同步以 Driver 能恢复的内容为准。

心跳过期不代表外部 CLI 已退出。带 launchId 的终端占用需经交接确认，不能只按
90 秒心跳超时解锁；退出回调失败会保留占用并重试。

新启动的入口只可使用一次。cmux 保存的恢复命令仍指向该入口，已结束或已交接
的会话不能从旧窗口重新取得写权，需从 Kaus 重新打开。这也限制了 cmux 对这些
会话的自动重启、休眠后恢复。已有旧版启动脚本缺少进程身份时，需要先手动退出
终端中的 Agent。脱离 Agent 进程组独立运行的服务不属于该停止操作的范围。

## cmux 自带行为与验收边界

本次核对的 cmux 版本为 0.64.20。其原生脚本会按自身设置启用状态、通知、
Feed 等钩子；Kaus 不另装一套并行通知，也不修改 cmux 的全局设置。

以下行为超出界面显示，来自 cmux 的脚本，需在升级兼容检查中保留：

- Codex 钩子注入可能包含 `--enable hooks`、`--dangerously-bypass-hook-trust`。
  后者改变钩子信任校验，与 Agent 工具权限、沙箱档位不是同一个开关。
- Hermes、Amp 脚本会尝试合并安装各自的钩子或扩展；Hermes 同时记录原生钩子
  同意状态。它们可能修改对应 Agent 的配置文件。
- Claude、Codex 的计算机操作 MCP 附加行为仍由 cmux 的本机设置与脚本决定。
- 用户自装钩子和 cmux 的组合、第三方修改版 CLI、后台独立进程，以及所有引擎
  的真实模型回合都需要各自的实机验证。

自动测试覆盖参数和配置目录保留、进程组停止、终端前台输入、重复启动拦截、
进程身份不匹配、停止失败保持锁定、心跳过期、退出回调重试和双按钮交互。
本机 cmux 四种脚本另以临时 HOME、模拟原生 CLI 和本地替身服务验收开启与关闭
共八种情况；不调用模型、不改用户 Agent 配置，也不将安装包脚本纳入仓库。

参考：[cmux Agent hooks](https://github.com/manaflow-ai/cmux/blob/main/docs/agent-hooks.md)。

# 模型与 effort 动态发现验收 · 2026-10-24

本页保留较早一轮的协议与生成证据。随后产品标准明确为“当前连接实际提供的可选模型”，并补齐原生历史隔离，见 [探测隔离与当前连接模型](discovery-isolation-20261024.md)。下表中未登录返回的公共目录数量不再作为现行菜单结果；早期临时 Project/数据库不能代替后续增加的原生历史隔离。OpenClaw 草稿探测现已改为只读 Gateway 目录，正常会话切换仍走会话级操作。

## 原因与统一规则

此前共用读取已经存在，但旧预设的能力声明仍能拦截实际会话返回的配置；已有会话还会用安装时的能力快照覆盖刚发现的控件。因此只看到部分引擎生效，不能作为全引擎适配完成的依据。

现在普通草稿、已有会话和组长配置使用同一套原生配置发现与校验。ACP 优先读取当前会话的 `configOptions`，按标准 `category` 识别模型、推理强度和工作模式，原样回传引擎给出的配置 ID 和选项值。旧版 `models`、`session/set_model` 和已验证的 effort 后缀格式仅在原生标准项缺失时使用。没有品牌白名单决定控件是否出现。

- 选定模型后，通过无提示词的临时会话获取该模型的真实 effort 选项；探测结束即关闭连接。结果按绑定与模型分别缓存，不改变原生全局默认配置。
- 运行中的修改发给同一原生会话；有完整配置回执时，必须确认实际值再保存。模型变更带来的 effort 重置和选项移除跟随原生回执。
- 当前会话选项优先于安装时快照。开始、结束一轮后刷新；页面重新获得焦点时复查。配置文件或启动程序变化会使后端目录缓存失效，暂时失败采用短缓存和有限重试。
- 成功创建会话但没有提供模型选择器时，沿用原生默认模型；不根据旧预设制造模型下拉。创建失败仍按实际登录、连接或协议错误处理。
- Project 配置、技能隔离、会话审批、协作组独立上下文保持原范围。组长保存配置时也校验选定模型的新选项。

标准字段、选项值和模型列表的变化可以自动跟随。原生协议新增一种操作机制、删除接口或修改技能加载机制时，仍需调整驱动；自动发现不能替代这种协议适配。参考：[ACP Session Config Options](https://agentclientprotocol.com/protocol/v1/session-config-options)。

## 实测发现并修复

1. Codex 新版已经提供标准模型配置，旧适配仍拼接 effort 后缀，导致换模型返回参数错误。标准路径现传原始模型值，旧存量选择仍可恢复。
2. Kilo 的 effort 随模型变化。初始模型的档位不能复制到所有模型；通过统一的模型预览探测修正，现可取得原生接受的配置。
3. OpenClaw 的模型选择来自 Gateway，不能向 ACP 发送 Kaus 合成的配置项。草稿预览和实际切换共用会话级 Gateway 操作，核对原生会话身份及确认值。
4. OpenCode 的大权限清单经管道输出被原生进程提前退出截断。改为私有临时文件承接完整输出；文件随读取结束删除，技能隔离检查没有放宽。该检查函数也由 Kilo 共用。
5. 普通会话的动态能力不再被静态安装能力覆盖；组长也读取所选模型的配置，避免两条路径漂移。
6. 本地冷启动复查发现 `/api/events` 在异步响应中同步扫描技能目录，阻塞模型与会话列表请求。首帧现复用后台快照，首次扫描放在线程中执行；目录监听在进入依赖和归档目录前剪枝。技能配置、继承和运行隔离未改动。

## 仍需处理的本机条件

- Claude Code、Qwen、Pi、Cursor、Grok、Command Code、Kilo：在相应原生入口完成登录，返回 Kaus 后复查。DSH / DeepSeek ACP、Gemini CLI：完成对应原生密钥配置。
- OpenCode：更换已过期的服务密钥。原生错误明确指出重新登录不会续期该密钥。
- OMP、ZCode：先在原生配置中建立可用模型。当前结果不能认定为引擎永远不支持选择器。
- OpenClaw：恢复原生 Gateway 连接再做生成验收。
- Goose、Crush：仍属于原生启动/生成故障待定位；没有归类成“不支持”。需先获取原生独立运行的具体诊断，确认配置与账号，再验收 Kaus 同一路径。

这些事项不需要修改产品方向，也不要求用户重复接入已有账号。没有把任何一个登录动作代为完成。

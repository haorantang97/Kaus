## 修复顺序与实现

1. **固定 Hermes 运行实例的技能版本。** 使用选择清单和源内容哈希生成不可变目录，实例启动后绑定该目录；项目记忆、会话库、Agent 新生成的技能分别持久化。新技能进入下一版本，不能覆盖正在使用的目录。
2. **分离全局来源与项目启用状态。** 全局 inventory 保存来源；工作区禁用映射为该项目的阻断记录。验证母项目、子项目、兄弟项目和重复来源，不因单项目配置删除共享目录项。
3. **明确用户是否要求受管技能。** 当前解析器可能自动产生空选择；这不能直接解释为用户要求禁用所有技能。区分原生模式与显式受管模式，再根据真实加载结果返回 native/applied/unsupported/pending。
4. **按原生加载器补适配。** 普通对话、Group 成员、组长、冷续接和终端共用同一策略。优先复用 Hermes 已有 guard；Pi 可通过原生 `--no-skills` 与 `--skill` 参数控制；OpenClaw 要把选择映射到 Gateway 的项目 Agent 配置；Gemini 需要覆盖内置、扩展、用户和工作区各来源。其余引擎分别核验加载入口，不假定 ACP 提供通用隔离接口。
5. **补真实模型验收。** 合成测试先验证选中可用、未选不可用、插件旁路、并行实例和续接；登录后再验证真实模型调用和任务质量。登录不是上述代码适配的前提。

另外记录了 MCP 冷续接的协议缺口候选：当前 load 请求传空 mcpServers。是否丢失配置取决于各引擎恢复语义，后续需录制协议并选一家具体验证后再修改，不能据此认定所有引擎均有故障。

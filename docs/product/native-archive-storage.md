# Kaus 对话保存与已有对话

2026-10-17：普通 Kaus 对话自动保存并归属 Project；用户可从项目菜单选择“添加已有对话”，把原生客户端的旧对话纳入该项目。首次使用无需迁移历史。

## 普通对话

- 原生 Agent 继续使用自己的本地目录和清理规则。Kaus 不修改其保留期限或账号配置。
- Kaus 保存会话身份、Project 关系、事件顺序、审批、运行状态和书签。
- 新增文字只有在本地原生记录完整、身份稳定且逐字核对一致时，才替换为原生引用。工具、附件和未完整适配的内容仍由 Kaus 保存；已有内容不追溯删除。
- 原生读取与引用机制是会话运行时的一部分，独立于旧对话的项目关联。

## 添加已有对话

从 Project 菜单进入，目标项目固定。选择 Agent 后显示其本机旧对话，可搜索、批量选择并添加。读取适配首批覆盖 Codex、Claude Code、Hermes；运行适配数量与历史读取适配数量独立计算。

Kaus 保存来源索引和项目关系，正文与附件按需读取原件，不创建独立归档副本。原件仍由 Agent 自己管理。添加后的记录出现在所属项目内；历史阅读与跨 Agent 接续共用现有读取能力。

原生历史是可阅读的已有记录。需要开始工作时使用“接续”创建关联新会话并审阅草稿，不把原生旧记录伪装成已运行的 Kaus 会话。

资料库保留笔记功能。独立档案管理页面不再作为产品入口；备份恢复、历史回收站、原始 JSON 查看等兼容实现不进入普通用户流程。旧数据保留。

Kaus 自身对话的归档/恢复属于正常会话管理，在“设置 → 已归档”维护。

## 跨 Agent 接续

Kaus 对话仍可在同一应用窗口创建关联的新会话。用户选择目标 Agent、审阅交接材料后进入草稿，发送后才运行；目标使用当前 Project 下对应 Agent 的配置。

交接正文和用户选择的附件会生成新会话拥有的实际文件，不能把原生文字引用规则理解为所有功能均不产生副本。隐藏推理、原生进程、认证与源 Agent 专属配置不随交接迁移。

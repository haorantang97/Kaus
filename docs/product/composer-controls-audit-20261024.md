# 对话输入与参数审查 · 2026-10-24

用户报告：点击输入区出现硬矩形描边；Codex 模型和 effort 消失；其他引擎参数位于中间且不可修改。本轮确认并修复 Kaus 前端样式及配置读取问题。本机 Codex、Claude Code、Hermes 的实际连接均返回了可切换能力。

## 原因与修复

| 问题 | 原因 | 当前行为 |
| --- | --- | --- |
| 输入区内出现矩形 | 全局 `:focus-visible` 为 textarea 重新添加 outline，覆盖输入组件的无描边样式 | 公共控件及各功能样式移除额外焦点矩形；键盘操作通过原有控件底色、链接下划线和输入区域边色获得反馈 |
| 参数在工具栏中间 | 原 spacer 与发送按钮各占一个自动左边距，分走剩余空间 | 模型、effort、发送按钮组成统一右侧区域 |
| Claude Code 新对话不显示 effort | 草稿页忽略了原生会话配置提供的推理默认值和档位 | 草稿与已有会话共用解析，按会话覆盖、模型配置、原生默认及引擎配置确定值 |
| 一次读取失败后参数持续缺失 | 请求异常转为空设置，缺少恢复路径；切换引擎才触发重读 | 失败结果不缓存为有效配置；最多两次自动重试，回到窗口或恢复网络可再次读取；切换页面后忽略迟到结果 |
| 已有对话参数消失或锁住 | 次要的引擎状态请求与绑定读取共享异常处理，状态查询失败会清空已成功取得的绑定 | 次要状态查询独立处理；模型目录、有效值和能力按同一份快照更新 |
| 已知可选值仍被隐藏 | UI 额外要求存在默认值，尽管原生已返回选项及切换能力 | 有真实选项和写入能力即可选择；缺当前值时显示中性名称，不自动选第一项 |

实际客户端曾出现 Codex 参数为空，切换引擎后恢复；首次失败响应没有保存，不能断言那一次请求的具体网络原因。以上恢复缺陷已由代码路径与故障注入测试确认。

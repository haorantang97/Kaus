# 首次接入、跨 Agent 接续与客户端信息整理

> 当前范围已收束为仅管理 Kaus 发起的对话；外部旧历史关联及独立历史库界面已撤下。以 [对话保存范围](native-archive-storage.md) 为准。以下保留历史交付记录。

2026-10-17。本轮保留现有配置、原生会话目录和 Kaus 数据；原生清理策略继续由各 Agent 管理。

## 已落地行为

- 历史关联只建立索引。原件已清理的条目不进入普通列表；恢复原件并刷新后可重新出现。客户端没有“来源缺失”状态，也没有“独立归档”的创建选项。既有保存内容仍可读取、导出和恢复。
- 路径选择优先进入系统文件夹界面。页面默认显示文件名、目录名和项目名；协议码、JSON、堆栈、内部位置进入主动展开的详情。真实操作失败保留简短原因和恢复动作，后台探测与轮询降级不制造常驻提示。不改写用户或 Agent 正文中的代码与路径。
- 首次手动接入一个 Agent 产品后，有界读取原生技能目录，发现的全局技能进入母 Project 的对应 Agent 分组。读取完成后自动展示一次既有技能树，可以调整、完成或跳过；跳过状态持久化，升级、重连和同产品其他通道不重复打扰。拖动与菜单共用分配接口。
- “用其他 Agent 接续”在当前应用窗口打开新的关联对话：选择目标、审阅可编辑交接、确认附件，然后进入草稿；用户发送后才运行。来源会话、引擎和配置保持原样。
- 接续使用公开正文的有界摘录，并提供可点击的完整记录文件。只携带用户确认的附件，目标使用其 Project 的通用配置和目标 Agent 专属配置。原 Agent 的隐藏状态、内部思考和专属技能不会作为运行配置迁移。
- 交接记录中的已选附件链接可解析到新会话拥有的副本；原件删除后仍能打开。本地系统附加引用只提供给驱动，不进入显示的用户正文。这里的任务材料复制与历史索引是不同用途，并非承诺磁盘零占用。

具体行为见 [首次接入](skill-onboarding-20261017.md)、[跨 Agent 接续](cross-agent-continuation-20261017.md)、[信息显示检查](quiet-ui-audit-20261017.md)。

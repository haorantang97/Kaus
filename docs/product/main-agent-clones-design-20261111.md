# 主 Agent 分身 · 设计稿（2026-11-11，待项目负责人定）

依据：`docs/handoff/product-decisions.md`「主 Agent 分身与后台事务」「主 Agent 分身的定位」「Agent 自查的形式」「项目记忆：有效期与重复合并」。本稿只写方案，不含代码。文末三个问题要负责人定。

## 1. 要解决什么

几类事务需要模型，但不该让用户每次手动发提示词：

- 定时整理项目记忆：合并相近条目、作废过时条目、压缩索引。Kaus 自己按规则做的到期收起和完全重复合并（不调用模型）之外，剩下要判断的部分。
- 对话结束后提炼候选记忆。
- Agent 自查：已经单独做成导入名单里的入口，分身可以接管它的定时复查。

Kaus 不接自己的模型，所以这些事务交给用户已接入的 Agent，花的是该 Agent 的额度。

## 2. 分身是什么

- **主 Agent**：用户选定、挂在根 Project 上的那个 Agent（某条 Binding）。
- **分身**：同一个 Agent 在根 Project 上的另一条 Binding。领域模型已经支持这种结构：同一 Project 挂多条同 Backend 的 Binding，用 binding id 的第四段 discriminator 区分（`app/projects/models.py` R-09）。
  - 每个分身有自己的说明、权限档和模型（可以选更便宜的）。
  - 所有分身共享项目记忆。它们本来就在同一个 Project，经内置 MCP 读写的是同一份记忆，不需要旧实现里的软链接。
- **分身仍是普通 Agent**：能在侧栏里像普通会话一样打开、正常对话。此外它有一个独占面板，把它负责的事务做成流程和按钮。
- **与旧实现的区别**：旧实现只在 Hermes 上，靠档案软链接和 `SOUL.md` 开头的模式标记，2026-11-02 已删除。通用版完全走 Binding、Project 指令和内置 MCP，不碰任何 Agent 的主目录，不认识引擎名。

## 3. 两个分身

| | 后台分身（低权限） | 配置分身（高权限） |
| --- | --- | --- |
| 原名 | steward「后台模式·低权限」 | architect「配置模式·高权限」 |
| 负责 | 定时整理记忆；对话结束后提炼候选记忆；Agent 自查的定时复查 | 整理配置：导入能力、调整技能树、改 Project 指令（经控制 MCP） |
| 能做 | 读写项目记忆、读配置；提交建议（候选记忆、绑定建议） | 在内置 MCP 之外，再加控制 MCP 的配置工具（需新增，见下） |
| 不能做 | 改文件、执行命令、改配置 | 删除 Kaus 对象；不经用户确认就落盘 |
| 启动方式 | 按计划自动运行，也可以从面板手动运行 | 只由用户在面板里或对话里发起 |
| 默认 | 可选，默认关 | 可选，默认关 |
| 落实权限 | 以只读权限（plan / read-only）启动；不附工作目录或附空目录；只附内置 MCP | 普通权限，附控制 MCP |

**产出都先作为建议**：候选记忆进「待确认」，用户在面板里逐条确认或一键全收；配置改动先列出变更，确认后再写。这和「Agent 自查只读、结果由用户确认」是同一口径。

**控制 MCP 的缺口**：控制 MCP 现在不改 Project 配置（product-decisions「总控 Agent」）。要让配置分身改技能树和指令，需要给控制 MCP 加配置类工具，或者让配置分身也只提交建议、由面板落实。后者更稳，建议先这样做。

## 4. 面板

面板里放：

- 分身开关、模型、计划（例如每天一次、对话结束后）；
- 每类事务的「立即运行」按钮；
- 最近几次运行的结果，以及待确认的建议；
- 「打开对话」：进入这个分身的普通会话。

面板放在哪里，候选位置：

1. **设置里的「主 Agent」页**（建议）：全局只有一个主 Agent，放在设置里最好找，也不和项目页抢位置。
2. 根 Project 的项目页加一个分区：主 Agent 本来挂在根 Project 上，位置上一致，但子 Project 页看不到它。
3. 侧栏的独立入口：最显眼，但侧栏现在只放会话和项目，会多出一类对象。

## 5. 主 Agent 怎么选

- **建议**：第一次接入 Agent 时，第一个接入的自动成为主 Agent；之后可以在面板顶部改，并提示「分身会随之换成新 Agent」。
- 换主 Agent 时，旧分身的 Binding 归档，不删除；它们的会话保留，可以查看。
- 没有主 Agent 时，面板只显示「选择主 Agent」。
- **能当主 Agent 的条件**：驱动能按次限制权限（只读）、能加载内置 MCP。不满足的在选择列表里置灰，并附原因码。

## 6. 运行与安全

- **调度**：后台运行用现有维护循环（`MaintenanceLoop`）调度。
  - 只在 Kaus 运行时执行，不装系统级定时任务。
  - 同一事务同时只跑一次；上一次没结束就跳过本次。
  - 遵守会话的运行所有权规则：发出后等终端事件，忙时不自动打断重试。
- **对话结束后提炼**：只读取已结束对话的公开记录（用户与 Agent 的消息），不读隐藏思维链；每条对话只提炼一次。
- **记录**：每次运行写一条运行记录，内容包括事务、分身、模型、开始/结束时间、产出的建议数，以及失败的原因码。
- **测试**：普通测试只用协议 fake，不调用真实模型。

## 7. 分步

1. 主 Agent 的选择与面板骨架：开关、模型、打开对话。
2. 后台分身：手动运行「整理记忆」「提炼候选记忆」，以及待确认区。
3. 后台分身的计划运行。
4. 配置分身（如果要做）：先做成只提交建议、由面板落实。

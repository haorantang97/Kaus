# PRD：协作组里的人怎么说话（Group 协作策略 v1，2026-09-14 第三次修订）

写于 2026-09-14。补 v1.2 §1/§9.4 留白的那份「独立 PRD」。上半（§A）给产品方拍板，说人话；下半（§B）给开发代理，是规格。
**背景**：AD-153 把「用户就是协调者、不做 Agent 之间传话」写成了裁决，那是 Fable 把产品方「这些功能哪来的」的提问误读成了取消。产品方 2026-09-14 明确：**成员必须能在这个窗口里共同工作、实际沟通配合，否则组没有意义。** 本 PRD 通过后 AD-153 按 §B.7 修订。

## A. 一页人话（给产品方）

> **2026-09-14 修订**：产品方否掉了第一稿的「三档按钮」（手动转 / @ 转 / 讨论表单）——「我应该不需要这么多操作」。改成下面这样：**房间自己会转**，你只管说话。

### A1. 组是一个房间
打开一个组，你看到的是一条**时间线**——你说的、每个成员说的、系统事件，按时间排在一起。每一条都写着**谁说的、第几轮、发给了谁**。任何一句话都追得到发起人（AD-153 唯一留下的底线）。

### A2. 你只做一件事：说话
你在房间里发一句，比如：
- 「你们针对『个人多 Agent 系统怎样才算真正有用』讨论一下，最后给我一个结论。」
- 「A 和 B，你们刚才的观点冲突了，辩论一下，最后给我一个合适的答复。」

然后**房间自己转**：每个成员都看得到房间里发生的一切；轮到谁，谁就接着说；没话说的就沉默；谁认为可以收口了，就给你一个**最终答复**，房间安静下来等你下一句。你不需要点「转给」，不需要填「几轮」，不需要选人。

**只有一个按钮：「停」。** 房间在转的时候它才出现。

### A3. 房间怎么知道该谁说、什么时候停

> **2026-09-18 第四次修订**：前三版依次是「6 轮上限 + 谁想收口就写最终答复」→「每人每轮写 `[状态]`，全员可收口才停」→「可收口是粘性的，`@` 召回」。产品方两问打穿了后两版：「如果对话依靠别人 `@`，而不是模型的主观意愿，怎么能准确控制停止？别的模型怎么会知道他还有没有话说？」以及「你们随便挑两个人辩论一下——现在是只触发两个还是全员都收到？」
>
> 于是去读了六家（AionUi / Omnigent / Grok Bot / AutoGen / Semantic Kernel / AgentScope 2.x）的源码，见 `docs/audits/termination-comparison-2026-09-14.md` §7。三条硬结论：**六家零举手**（没有一家让没被点名的人主动插话）；**六家零投票**（没有一家让每个发言者自报做完没做完再汇总——第二、三版是六家都没有的东西）；**收口人 = 判定人 = 选人者三合一**（凡是有人写最终答复的地方，那个人同时决定下一个谁说、什么时候停）。
>
> 这一版把三合一放在**组长**身上，而且不多花一次引擎调用。删掉整套表态机制。

> **2026-09-19 第五次修订（裁决 B）**：批次四十八真机第一份记录（`docs/quality/reports/2026-09-19-group/REPORT.md` §3 ②③④、§4）里，三场讨论中**评审、打杂在每一轮结尾都 `@下一位`**（评审→`@打杂`、打杂→`@写手`）——把「想让谁接着说就写 @名字」读成了传话筒。按第四次修订的「三者同权」，这些接力 `@` 会把人塞进下一轮，于是**只要有一个成员这么写，终止 3「组长不点人 → 停」就永远到不了**；三场都是靠组长写「最终答复」才停的。
>
> 产品方裁决（2026-09-19）：**B——下一轮队列只认组长的 `@`。** 成员的 `@` 组长看得见（它读全场），当请求处理。这是 AionUi / SK / MagenticOne 的纯形：路由只在一个人手里。结构上堵死传话筒，不靠模型听话。见 `docs/tasks/batch50-leader-only-routing.md` §0。

> **2026-09-20 第六次修订**：第二次外派（`docs/quality/reports/2026-09-19-group-2/REPORT.md` §8）里，组长那句 `@评审 请回应打杂最后的追问，下一轮由你发言` 解析成 `mentions=[评审, 打杂]`——**打杂是被裸名匹配捎进去的**，组长只 `@` 了评审，「打杂最后的追问」是在谈论他。那一场恰好无害，但第五次修订之后**路由只在组长手里**，而主持人必然要在话里提成员（「评审的质疑成立」「打杂说的那个边界已经清楚了」）：裸名匹配会把这些人全塞进下一轮，等于**组长谈论谁就等于点名谁**。
>
> 产品方裁决（2026-09-20）：**谁在说话决定用哪把尺子。** 用户的开场话裸名照认（那是给人的方便，他不必为了让房间转起来去学一个符号）；**组长的路由只认显式 `@名字`，正文里裸提的名字不算**；成员的话本来就只记录不路由。`LEADER_NOTE` 已经在教组长写 `@名字`，再加一句说明裸名不算。见 `docs/tasks/batch51-leader-explicit-at.md` §0。

- **组长**：每个组有一位，默认是最早加入的那位（这正是前三版里悄悄写最终答复的「队首」，现在露出来），停靠栏有标记，你可以换。它是普通成员，不常驻、不多跑。
- **轮流说，组长永远最后一个**：一轮 = 该说话的人各说一次，组长排最后。它开口时已经读完了这一轮所有人的话。
- **你点名了就只有被点的人说**：写「A 和 B 辩论」或 `@A @B`，其他人这一轮旁观。没点名 = 所有活跃成员都说。组长若在组里且活跃，**无论点没点它，都排在最后**——房间永远要有一个收口的人。
- **第一轮谁说由你定**（你点名或全员）；**之后每一轮谁说由组长定**——只有组长那段话里的 `@名字` 算数，**它正文里裸提的名字不算**（第六次修订：主持人必然要在话里提人名，提一个就多拉一个人进下一轮）。成员想让谁回应、或自己还想再说，写在话里（可以 `@`），组长看得到、由它安排。
- **想再说一次 → 在你这段话里写明（可以 `@组长`），组长决定点不点你**。这就是「举手」，形状是六家都有的「发给判定人」。
- **停下来的条件，按优先级**：
  1. 你按「停」/ 打「停止」→ 立刻停，不收口。
  2. **组长以「最终答复」开头** → 那段就是结论，高亮成卡，房间停。别人写「最终答复」不算。
  3. **一轮结束，组长没点任何人** → 组长这一轮最后说的那段就是结论（它读完全场后没再点任何人）。房间停。
  4. **安全阀**：轮数上限（默认 **12**，只防成本失控）→ 给组长单独发一条「到此为止，收成用户要的东西」，它的回复标最终答复。不硬切。
- **一轮就结束的**（「介绍一下自己」）：全员各说一次、组长最后说完没点任何人 → 停。组长那一段就是收尾，不再多一条总结。
- **组长说了「随便挑两个」的那种话怎么办**：你说「你们随便挑两个人辩论」，房间没认出名字，全员进队列、组长最后。组长第一轮说「我抽 A 和 B，@A @B」——下一轮就只有 A、B（和组长）。这不是房间猜意图，是组长在做组长的事。

### A4. 成员知道自己在房间里
每条发给成员的消息前面有一段固定格式的房间说明：你是哪个组的谁、组里还有谁、**这一轮房间里新发生了什么**（上次你说话之后别人说的）、三条约定（点名 / 略过 / 最终答复怎么写）。这不是把整包上下文偷偷塞进去——它是固定格式、每条可见、只含房间里已经公开的话。

### A5. `@` 保留，且是唯一的续聊方式
你 `@A` 就是"这一轮只有 A 说"（**你写裸名也算**，不必学符号）；**之后每一轮的 `@` 只认组长写的**（第五次修订），**而且只认它写的显式 `@名字`**（第六次修订）——成员回复里的 `@B` 是写给组长看的一条请求，由它决定下一轮点不点 B。输入框里打 `@` 弹出成员列表 + `@所有人`（Grok Bot 的做法，2026-09-17 截图）。

### A6. 组长
每组一位，默认最早加入者，可换。它不是新的一种 agent，是成员上的一个标记。它做三件事：分工（读你那句话，点该说的人）、续聊（每轮最后说，点下一轮的人）、收口（写「最终答复」或不点任何人）。这三件事六家参考项目都是同一个人做的。

### A7. 明确不做
邮箱 / 任务板 / 共享工作区；每人每轮表态；自动总结（组长最后那段就是）；Context Packet 自动注入；房间猜意图（名字之外的一切不猜，交给组长）。

### A8. 已拍
1. 兜底轮数 **12**，触顶让组长收口而不是硬切。
2. 「最终答复」高亮成卡、房间安静。只认组长。
3. 组长 = 成员标记，不常驻，默认最早加入者。

## B. 规格（给开发代理）

### B1. 数据模型（`kernel/app/collaboration/models.py`）
- `CollaborationMessageKind` 新增：`member_turn`（成员一轮的最终文本）、`relay`（规则或用户转发的一条）、`discussion`（③ 的一轮控制记录）。既有取值不动。
- `author_type = "member"` 开始真的写：`member_turn` 的作者是该成员；`relay` 的作者仍是**被转的那条的作者**（说话人不变），`metadata.origin` 说明怎么来的。
- `metadata` 约定键：
  - `origin ∈ user_sent | relay_by_user | relay_by_mention | discussion_round | coordinator`
  - `round`（③ 的轮次）、`hop`（② 的跳数，从 1 起）、`sourceMessageId`（转自哪条）、`mentions[]`（解析出的成员 id）、`deliveries[]`（沿用 AD-153 的状态字）
  - `member_turn` 另带 `runId`、`toolCount`（这一轮跑了几个工具，只给数）、`truncated`（正文超过 4000 字截断标记）。
- Group 级设置（`CollaborationGroup.settings`，可空 JSON）：`relayBudget`（默认 10）、`coordinatorMemberId`（可空，v1 不启用）。
- Group 级运行态（新表或 `settings` 内嵌，允许实现自选）：`relayEpoch`（用户每发一条 +1）、`hopsUsed`、`discussion {memberIds, rounds, current, topic, status}`。

### B2. 成员回复进时间线（批次四十五 a）
- 订阅 SessionHost 的事件（现有 `EventSubscription` / group 事件桥）：成员会话的 `run.completed` → 取该轮最终 assistant 文本（Reducer 侧已有"这一轮的正文"口径；没有就取最后一条 assistant 文本）→ 写一条 `member_turn`。`run.failed` / `run.interrupted` 也写一条（`metadata.outcome`），正文可空。
- 只记录**是组成员期间**的轮次（`joined_at ≤ run.started < left_at`）。一条会话同时在多个组：每个组各记一条。
- 幂等：`(group_id, conversation_id, run_id)` 唯一，重放不重复。
- `GET /groups/{id}/messages` 形状不变，只是多了这些 kind；前端时间线按 kind 渲染（成员气泡带成员名与引擎）。
- `kaus/group.changed` 的 `change` 加 `member_turn`，沿用 `messageId`。

### B3. 房间说明（批次四十五 a）
纯函数 `room_header(group, members, recipient) -> str`，投递前拼在用户文本前，格式固定：
```
[协作组「<title>」] 你是「<recipient 显示名>」（<引擎>）。组里还有：<A>（<引擎>）、<B>（<引擎>）。要对某位成员说话，在回复里写 @<名字>。
---
<用户原文或被转的原文>
```
- 显示名 = `roleLabel` > 会话标题 > 成员 id 尾段；重名时加后缀 `#2`，且 `mentions` 解析用同一份表。
- 只在**投递给引擎**的文本上加；时间线上存的仍是原文（`metadata.roomHeaderVersion = 1` 记一下加了）。
- 已暂停 / 已离开的成员不列入"组里还有"。

### B4. 房间循环（批次四十五 b）——替代第一稿的 ①②③

**状态**（Group 级，`settings` / 运行态）：`roundCap`（**安全阀**，默认 12，1–50）、`thread {epoch, round, speakerQueue[], spectators[], status ∈ idle|running|stopped|final|exhausted, startedByMessageId}`。用户每发一条广播 / 定向 → `epoch += 1`，新线程。

**谁该说**（`speakerQueue`，第四次修订）：
- 解析用户消息里的点名：`@名字` 或直接出现成员显示名（B3 的表）；命中 ≥1 → 队列 = 命中者（按加入顺序）；否则 = 全体 `active` 成员。定向发送（`targetMemberIds`）等价于点名。`@所有人` 是显式的「全体」。
- **组长（`leader_member_id`，见 B6）若 active，无论是否命中，一律追加到队列末尾**（去重）。它是每一轮的最后一位。
- 其余 active 成员 = `spectators`：不排队、不投递（游标 `lastDeliveredSequence` 让他们下次被点到时一次补齐）。
- **下一轮队列**（第五次修订，裁决 B；第六次修订收窄尺子）= **组长本轮 `member_turn`** 里 `resolve_mentions(..., explicit_only=True)` / `resolve_everyone` 的命中（顺序按组长写的次序），剔除非 active 与组长，末尾追加组长。`explicit_only=True` 时候选只有 `@名字`，**不回退到裸名**；这个参数默认 `False`，所以用户那句开场话与 `metadata.mentions` 那笔取证照旧认裸名。**成员 `member_turn` 里的点名不进队列**——它是写给组长看的一条请求，组长读全场时看得到。组长本轮略过 / 投递失败 → 队列为空 → 终止 3 / 5。
- **`metadata.routed`**（第六次修订）：组长那条上另记一笔「真正进了下一轮队列的那几位」（不含它自己，按队列顺序）。它与同一行上的 `mentions`（宽尺子，他提到了谁）并排，时间线因此答得出「组长提到了打杂，但打杂没被路由」。
- 第 1 轮中，**组长发言里的点名把本轮剩余队列改写为被点名者**（「随便挑两个」的落法）：组长排在最后，所以这条只在组长不是最后一位时才有效果——即用户点名里含组长且组长不是最后时。实际上组长永远最后，这条等价于「组长的点名只影响下一轮」。留这句是为了把「组长不裁剪本轮」写成明确的规则而不是漏洞。

**一轮**：按队列顺序**串行**：投递给 speaker → 等它 `run.completed`（复用 45a 的旁观者）→ 写 `member_turn` → 下一位。串行是刻意的：并行会让两个人同时回一个已经过时的房间。

**投递内容**（扩 B3 的房间说明，纯函数 `room_delta(group, member, since_sequence)`）：
```
[协作组「T」] 你是「A」（引擎）。组里：A（你）、B、C。本轮发言人：A、B；旁观：C。
自你上次发言以来房间里的对话：
- 用户：…
- B：…
约定：发言顺序由组长安排，不用在结尾 @ 下一位。要让谁回应你、或你还想再说一次，在正文里写明（可以写 @名字），组长会看到并决定下一轮谁说。没有新内容就只回「（略过）」。组长每轮最后发言。
---
<这一轮要你回应的最新一条原文>
```
`since_sequence` 记在成员上（`lastDeliveredSequence`），每次投递后更新；第一次投递从线程起点算。

**终止**（第四次修订，替代表态解析 / 粘性收口 / 单人守卫；按优先级）：
1. 用户「停」/ 停止词（B10-1）→ `stopped`，不收口。
2. **组长**的 `member_turn` 以「最终答复」开头（`is_final`）→ `final`，停。**非组长的「最终答复」不生效**（记 `metadata.finalIgnored=true`，时间线不高亮；Semantic Kernel 的 `agents=[reviewer]` 白名单同形）。
3. 一轮结束，**组长没点任何人**（下一轮队列除组长外为空）→ 组长那条标 final，停：`member_turn` 标 `final=true, phase="closing"`，线程 `final`。不再单独投一条收口指令——组长说的时候已经读完全场。`round == 1` 同此（「介绍一下自己」）。
4. `round > roundCap`（默认 12，1–50）→ `phase="closing"`：单独投给组长一条「到达安全上限（N 轮），到此为止，请把上面的讨论收成用户要的东西：『<原话>』，只给结论」，其回复标 `final`。投递失败 / 跑失败 → system「收口没有成功：<原因>」并 `stopped`，不重试。
5. 一轮内没有一个人说出话（全略过 / 全投递失败）→ `idle`。组长也略过 → 同此。
6. 组长 `paused`/`left` 且组里无其他 active → `idle`，system「没有可收口的成员」。组长 `paused`/`left` 但有其他 active 成员 → **自动把最早加入的 active 成员标为组长**并写一条 system。
7. 用户新消息 → 无论当前状态都开新 epoch（旧线程若 running 先 `stopped`）。

**删除**：`parse_status` / `STATUS_PREFIX` / `READY_TOKEN` / `CONTINUE_TOKEN` / `normalize_gap` / `round_status` / `stuck_members` / `ready_members` / `effective_speakers` / `everybody_ready` / 单人守卫 / `LONE_SPEAKER_*` 文案 / `ThreadEndedReason.lone_speaker` / `closing_prompt` 的常规路径（只保留给终止 4）。测试单 L6 / L10 / L11 / L14 / L15 按 B8 改写。

**「最终答复」**：只认组长；判开头不判包含（`is_final` 不变）。

**`@` 接力**（第四次修订）：不再「提前到本轮下一位」。所有点名只决定**下一轮**队列（见「谁该说」）。理由：组长在最后，本轮插队会让被插的人说在组长前面又说在组长后面，破坏「组长读完全场再说」这条。`_relay` 删除。

**略过**：回复去空白后等于「（略过）」/「(略过)」/「[pass]」→ `member_turn(passed=true)`，时间线默认不显示（可展开「本轮 2 人略过」）。

**`@` 接力**：成员回复里 `@B` → 本轮后续队列里 B 提前到下一位（不增加轮数、不新开线程）；点到旁观者 → 把它拉进队列末尾。仍受 `roundCap`。

**记录**：每条 `member_turn` 带 `metadata {epoch, round, speakerIndex, deliveredSince, deliveredTo, passed?, final?}`；每次投递带 `deliveries[]`（沿用状态字）。`kaus/group.changed.change` 加 `thread_state`。

**端点**：`POST /groups/{id}/thread/stop`；`GET /groups/{id}` 带 `thread` 状态；`PATCH /groups/{id}` 可改 `roundCap`。**不新增「转发」「讨论」端点**。

**前端**：组头「第 k/N 轮 · 轮到 B」+「停」；`final=true` 渲染「最终答复」卡；略过折叠；成员栏组长带标记（可在成员菜单「设为组长」）；输入框 `@` 弹出成员列表 + `@所有人`，选中插入 `@显示名 `（含 `#2` 后缀）；成员正文里的 `@名字` 渲染成带头像的 pill（可选，见任务书）。**删**「已收口 N 人」。

**成本**：每轮 = 队列长度次引擎调用（组长算一位，它本来就是成员）。组长不额外跑；触顶收口多一次。`roundCap` 上限 50。

# MCP 管理（设计稿，2026-11-11）

依据：2026-11-11 项目负责人与开发方的讨论（`docs/handoff/product-decisions.md`「MCP 单个工具开关」「MCP 管理」两行）。负责人同日定入口放在设置里，第一步已实现，见 `docs/handoff/verification.md`「MCP 管理（第一步）」。

## 1. 为什么要单独的入口

技能树解决「分给哪些 Project」，这一点 MCP 和技能一样，沿树继承。但 MCP 还有技能没有的东西：连接方式、登录、连接状态、一组可以单独开关的工具。各 Agent 自己也是这样处理的：Claude、ChatGPT 在设置里有带图标的连接列表，点开关就跳到登录。Kaus 缺这样一个入口。

分工：
- **技能树**：MCP 作为一个整体，分配到哪些 Project；
- **MCP 管理**：MCP 本身的事——有哪些、连没连上、要不要登录、哪些工具开着、是否绑定在某个 Agent 上。

## 2. 两种东西要分开

| | 标准 MCP | 厂商连接器 |
| --- | --- | --- |
| 例子 | GitHub、Notion、Figma、Obsidian、Playwright | Claude 设置里的 Gmail、Google Drive；ChatGPT 里的 Gmail、日历 |
| 凭证在哪 | 本机配置（密钥）或各 Agent 自己保存的登录 | 厂商的账号与云端 |
| 能否给别的 Agent | 能 | 不能，只能在那家 Agent 里用 |

厂商连接器在 Kaus 里只读展示，标为 Agent 绑定，不可分配给其他 Agent。

## 3. 页面

一个统一列表，不按 Agent 分页面。分组：

1. **可用**：可以分配给任何 Agent 的 MCP（导入的、在 Kaus 里添加的）。每行：图标、名称、来源（从哪个 Agent 导入 / 在 Kaus 添加）、状态。
2. **需要处理**：需要登录、出错、来源配置已不在的。
3. **Agent 绑定**：只属于某个 Agent 的 MCP（规则判定、Agent 自查后用户确认、用户手动标记、厂商连接器）。每行注明绑定原因。

右上角「添加 MCP」：从目录里挑常用的一键加入，或手动填写。目录取自官方 MCP 登记表（Magpie 内置了约 500 条同来源的条目），第二步再做，第一步只支持手动添加。

## 4. 点开一个 MCP

- **状态**：已连接 / 需要登录 / 出错（附原始诊断）。需要账号登录的远程 MCP，按 Agent 显示是否已登录，因为登录凭证存在各 Agent 自己那里。
- **登录**：11-12 定为 Kaus 统一登录一次（OAuth），令牌加密存本机，开对话时带给任何 Agent；不调用各 Agent 自己的登录命令。
- **工具**：按 MCP 标准工具清单列出开关，设一次全局生效（见 product-decisions「MCP 单个工具开关」）。需要登录才能列清单的，登录前只能整体开关。
- **绑定**：显示当前是否绑定及原因；可手动「标为绑定」或「取消绑定」。规则判定为「原生 Agent 不支持隔离」的不可取消。
- **分配**：只显示它在技能树里分到哪些 Project，点击跳到技能树；不在这里改分配。
- **从能力库删除**：放在 ⋯ 菜单。

## 5. 导入时的连接状态

| 类型 | 导入后 |
| --- | --- |
| 本地运行、用密钥的 MCP | 不用重新配置。开对话时现读原配置里的密钥，任何 Agent 都能用，显示「已连接」 |
| 需要账号登录的远程 MCP | 原 Agent 继续可用；其他 Agent 显示「需要登录」，各自登录一次 |
| 厂商连接器 | 归入「Agent 绑定」，只在原 Agent 里用 |
| Agent 不支持这种连接方式（例如只支持本地运行） | 对该 Agent 标「原生 Agent 不支持」 |

## 6. 绑定的说明（所有出现绑定的地方统一口径）

两种状态，说明都要讲清后果：

- **Agent 绑定**：只有这个 Agent 能用，别的 Agent 用不到。默认在所有 Project 里给它，可以在技能树里调整。
- **原生 Agent 不支持隔离**：这个 Agent 每次运行都会加载它，无法按 Project 关闭。

出现位置与形式（按 AGENTS.md：图标 + 可访问名称 + 提示，正文不写长段解释）：
- 导入名单：置灰行旁一句短说明；
- Agent 自查窗口：顶部说明绑定机制与上面两种后果；
- 技能树：锁形标记，提示文字说明是哪一种；
- MCP 管理：「Agent 绑定」分组标题旁的说明提示；
- 手动「标为绑定」时：确认框写明后果「之后只有 {Agent} 能用」。

文案用简短专业的说法，不用口语化表达。

## 7. 分步

1. 页面骨架：统一列表、分组、状态、详情（含工具开关，接上正在做的单个工具开关）、绑定状态与手动标记、统一说明文案。
2. 登录：按 Agent 发起登录与显示登录状态。
3. 目录：从官方 MCP 登记表添加。
4. 另议：Kaus 统一登录与转发、MCP 汇总。

## 9. 实现时补充的规则（11-11）

- 列表多一组「未导入」：Agent 自己配置、还不在能力库里的 MCP，详情里只有「导入能力库」。
- 取消绑定 = 进入能力库，分到的 Project 里所有 Agent 都能用；规则判定的绑定被取消后不会因重新发现再判回。
- 导入的 MCP「从能力库删除」= 退回未导入，Agent 那边的原配置不动；在 Kaus 添加的则整条删除（含密钥）。
- 在 Kaus 添加的 MCP，环境变量值和请求头值一律按密钥加密保存，界面不回显。

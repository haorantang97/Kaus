# 能力导入与归属（2026-11-10）

本稿汇总 2026-11-09 至 11-10 项目负责人在对话中确定的能力归属、导入、加载与存储规则，取代 [首次接入技能分配](skill-onboarding-20261017.md) 里「接入即全部登记、默认归入母 Project」的做法，以及 [技能树](skill-project-tree.md) 中「原生能力一律是 Agent 专属能力」的前提。标「待确认」的条目尚未得到项目负责人明确同意。

## 1. 前提的变化

| | 旧前提（至 11-09） | 新前提（11-10 起） |
| --- | --- | --- |
| Agent 原有能力的归属 | 属于该 Agent：文件在 Agent 目录，Kaus 只整理，树上是「某某 专属能力」，只给该 Agent | 导入后属于 Kaus：存进 Kaus 能力库，按 Project 分配，Project 里所有 Agent 都能用 |
| 进树的方式 | 接入时全部登记，默认放母 Project | 接入时勾选导入，勾了才进树 |
| 没整理过时 | Kaus 不动，Agent 原有的全部加载 | 只加载树上的 |

**唯一的使用规则一直是：能力按 Project 分配。** 前提变化只改变「导入的东西归谁」，不新增规则。

## 2. 归属与加载

- **只认技能树**：不在树上的能力不加载。没勾选导入的、跳过的、Agent 那边新出现还没导入的，都不加载。
- **Kaus 能力（含导入的）**：存在 Kaus 能力库，分到哪个 Project，该 Project 里所有 Agent 都能用。
- **Agent 绑定能力**：归属仍是所属 Agent，只给它用，不进公共能力库。
- **原生 Agent 不支持关闭的**：做不到不加载，标为 Agent 绑定能力，提示「原生 Agent 不支持按项目隔离」。
- 不隔离 Agent 主目录：登录、历史、Agent 自己的设置都留在原处，原生界面里的对话互通保留（11-10 决定，参考同类产品均不隔离）。以后多账号时可选单独目录。

## 3. Agent 绑定能力的判定

三层，没有万能的单一信号：

1. **确定的**：Agent 程序自己维护、删了会被加回来的（如 Codex 应用每次启动写回的 `node_repl`、`cua_repl`，装在 Agent 应用包里的）；Agent 不提供关闭方式的。
2. **规则判断**：内容依赖该 Agent 专有工具或讲它自己（Hermes 的 `claude-code`、`codex`、`computer-use`、`hermes-agent`）；依赖它的账号登录或自带网关；用了它专有的格式或事件。
3. **其余**：按普通能力列出，由用户勾选。

「Agent 自己维护」不能单独作为判定：Hermes 的 44 个自带技能都由 Hermes 维护，其中作曲、PDF 等是可共用的领域能力。只绑定操作系统（如 `apple-notes` 只在 Mac 上可用）不算 Agent 绑定。

## 4. 接入时的导入

1. 登录成功后先出现**勾选名单**，列出该 Agent 原有的技能、MCP、插件；每项可展开看名称、简介、来源；有一键全选。
2. 三种状态：

| 状态 | 勾选框 | 标注 |
| --- | --- | --- |
| 普通能力 | 正常勾选 | 无 |
| Agent 绑定能力 | 灰色，不可操作 | 「Agent 绑定能力」 |
| 已在技能树中（别的 Agent 读同一个公共文件夹，已导入过） | 已勾，不可取消 | 「已在技能树中」，合并成一条 |

3. 导入后仍按 Agent 分区进入技能树（原有分组机制），新 Agent 的分组默认展开，旧 Agent 的配置不受影响。
4. **跳过**要二次确认：「不会沿用这个 Agent 的任何配置，它将以空白状态接入，确定吗？」
5. **找回未导入的**：技能树里该 Agent 分组的 ⋯ 菜单「导入能力」，重新打开同一份名单，只列还没导入的；也可以在对话里让 Agent 导入。长期可用。

2026-11-11 确认：Agent 绑定能力的灰色勾选框，含义是「不用选，固定给所属 Agent 用」。名单上方另有「Agent 自查」入口：让该 Agent 只读复核还没定的配置，点建议里的条目名即标为绑定（`app/capabilities/self_check.py`）。

## 5. 变化提醒

- 只查各 Agent 自己那边的配置，按 Agent 分组；导入进能力库的东西只在用户主动更新时变化。
- 每个 Agent 记一份上次确认时的清单（每项带指纹），检查时分出新增、移除、有更新。
- 自动检查：Kaus 启动时；用该 Agent 开对话时。手动检查：状态栏里的按钮。
- 状态栏在技能树里，每项可导入、忽略；已导入且来源变化的显示「有更新」，可同步。
- 有变化时技能树入口显示黄点，点开状态栏即消失，不管是否处理。
- 和「找回未导入的」是两个入口：变化提醒是临时状态，找回是长期入口。

## 6. 存储

- 导入时能力本体存一份进 Kaus 能力库，更新检查依赖导入时的指纹。
- 开对话时不再整份拷贝：运行目录用链接（同盘硬链接）指向能力库里的本体，旧运行目录定期清理。
- 插件按整包存在、整包分配（11-10 已实现，见 `docs/handoff/verification.md`）。Agent 自装的插件留在 Agent 目录，Kaus 只管开关；插件里的技能随插件走。
- MCP 只存启动定义，程序在原处运行。
- 公共文件夹（`~/.agents/skills` 等，多个 Agent 会自己读）里的同一个技能只登记一条；不搬动用户的文件。

## 7. 电脑操作（11-10 决定，同日已执行）

- 保留：同一时间只让一个 Agent 接管整个屏幕。最终定为 Agent 自己在接管前调用 Kaus 内置 MCP 的 `kaus_screen_occupy`、结束后 `kaus_screen_release`，先来后到；后台操作不上锁。
- 去掉：自动安装 CuaDriver、权限引导（交给插件自己）、防重复（交给用户分配时把握）、项目级「浏览器 / 桌面」开关。
- 电脑操作改为能力库里的普通插件，用技能树分发；Agent 自带的按本稿导入规则处理。详见 `docs/computer-use.md`。

## 8. 实现影响（供实现时对照）

- 数据：导入的原生能力从 `<agent>:skills` / `<agent>:mcp` 改为 Kaus 能力库条目（无 Agent 前缀）；Agent 绑定能力保留 Agent 前缀。需要迁移已有目录与分配行。
- 加载：所有接入 Agent 默认按树启用技能（托管技能范围）；MCP、插件按各 Agent 的关闭方式排除不在树上的。取消「新出现的照常加载」（`launch_delivery` 的 `nativeMcpNew` 规则）。
- 接入流程：`CapabilityOnboardingStep` 改为勾选名单 + 分配；跳过确认；Agent 分组 ⋯ 菜单加「导入能力」。
- 新增：每个 Agent 的已确认清单、变化检查、状态栏与黄点。
- 运行目录：`skill_execution/common.materialize` 改为链接，加清理。

## 9. 实现记录（2026-11-10）

已实现，测试见 `docs/handoff/verification.md` 同日条目。与上文的差异：

- **找回入口**：放在技能树顶栏的「导入能力」按钮（先选 Agent，再出勾选名单），而不是 Agent 分组的 ⋯ 菜单。原因：跳过或一项都没导入的 Agent 在树上没有分组，菜单会找不到。
- **自动检查的时机**：打开技能树或「治理」页、回到窗口、在变化面板里处理之后各检查一次（每次检查即重新读一遍各 Agent 的配置）。没有单独挂在「开对话时」；不做常驻轮询。黄点同时显示在技能树顶栏的「配置变动」按钮和「治理」页签上。
- **存储**：技能导入时复制进 `<数据目录>/capability-library/skills/<id>/`，运行时从这份副本取，运行目录里的支持文件硬链接到它（Agent 自己目录里的文件不链接，只复制）。MCP 只存来源位置，开对话时按原格式现读定义，密文只在内存里拼进本次启动参数。Agent 自装的插件包体积大，导入后仍从安装位置读取。
- **旧数据**：本规则之前接入的 Agent 保持原来的安排，直到对它用一次「导入能力」；那一次之后，没勾选的从树上移除、不再加载。
- **接入时直接关掉弹窗**：不算跳过确认，导入状态保持「未处理」，该 Agent 自带的能力（绑定能力除外）不加载，可随时从「导入能力」找回。
- **一项都不选点继续**：等同跳过，同样要确认。

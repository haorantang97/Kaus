# Group 发言路由（2026-09-24）

本页记录当前实现，替代旧文档中有关成员勾选发送的约定。资料与会话隔离另见 [Group 资料](group-materials.md)。

## 当前操作

- 成员列表不再提供收件人勾选框；成员菜单保留移出组、暂停、恢复和设为组长等操作。
- 普通发送只提交正文，不自动附带全体成员 ID。点击成员菜单的定向发送仍指定该成员。
- 浮窗右上角“关闭”仅隐藏浮窗。“关闭组”结束该组的协作，保留组记录，并按弹窗选择处理组内会话；当前没有重新打开已关闭组的界面入口，也没有删除组入口。

## 当前唤起规则

1. 用户消息显式传入目标成员 ID 时使用该集合；普通界面发送已取消这项自动赋值。
2. 没有显式目标 ID 时，`@所有人` 选择活跃成员；否则按成员显示名匹配正文，支持裸名字及 `@名字`。有匹配则选择匹配成员，没有匹配则选择全部活跃成员。
3. 组长追加到本轮队尾。默认组长是最先加入的活跃成员，用户可以换人。
4. 后续轮次只采用组长正文中的显式 `@名字`，再将组长追加到队尾。其他成员的点名是给组长的建议，不直接唤起成员。
5. 组长发布最终答复，或成功回复后未再点名，结束本次讨论。

这是代码规则路由，没有单独调用意图判断模型。用户没有点名的普通消息仍会让全体成员依次发言；仅在正文提到某成员也可能触发他。这些限制需要新的交互决策，不能当作已实现的智能分配。

## 本次修复

- 对话编号在迁移或恢复后可能重复。下一轮的点名证据现在必须位于本次用户消息之后，同时匹配本次轮次；旧讨论的点名不能参与。
- 失败或被中断的回复不产生最终答复标记，也不提供下一轮点名。组长执行或投递失败时，本次讨论停止并显示原因；不会自动换组长、重试或取消成员正在独立执行的任务。
- 历史记录中错误的最终答复标记在读取时屏蔽；原始消息及已有系统通知保持原样。

## 实例与验证

检查对象：多厂家验收-0921。用户的两次提问均由旧前端明确指定四位成员，因此正文中的“写手”“评审”未参与首轮路由。写手为组长，所以每轮最后发言。写手的 OAuth 会话过期导致执行失败，旧代码又把失败当作正常收口。第二次提问还混入了旧讨论的组长点名，额外触发第二轮。

自动验证：190 项协作组后端测试、651 项前端测试、组件边界检查、类型检查及生产构建通过。新回归覆盖定向问评审、失败组长不收口也不继续点名、编号重复不复用旧点名、无勾选发送、空组及暂停/恢复。

## 待决定

普通消息是否改为“先交给组长；简单问题直接回答，需要协作再点名”。本次没有修改这项默认策略。若采用，应同时确定显式点名是否还需要组长复述、组长失败时如何交接、用户要求自由讨论时如何启动；无需给 Kaus 添加默认底层模型，可以由所选组长使用自己的模型判断。

# 同一原生会话在 Kaus 与 CLI 间往返

2026-10-24。使用原有 SessionHost → SurfaceCoordinator → TerminalLauncher，不另建对话存储。下文分别记录真实模型、原生组件和本机模拟模型的结果。

## 产品约定

- 正常对话保留当前连接的原生登录、配置、历史目录和会话 ID。“在终端打开”接续这一条会话，返回后读取终端新增的公开消息。
- 正常 Kaus 对话出现在 Codex 原生桌面列表属于应保留的互通；Kaus 不主动创建另一扇 Codex 聊天窗口。
- 测试和模型发现单独使用临时原生目录及 Kaus 数据库，退出前回收进程。此规则不修改普通用户的数据路径。
- 切换后继续使用同一 Project 的技能和 MCP 范围。不可为了开放终端而放开未选择的技能。
- 同时只有一侧持有写权。终端退出或“结束终端并切回”后同步记录并恢复 Kaus 输入；仅返回页面用于查看。

## 已补齐的接线

| 范围 | 实现 |
| --- | --- |
| 共用 ACP 路径 | 终端使用会话已经准备好的运行环境，并通过统一的 adapter hook 准备原生存储和配置。宿主没有按品牌维护另一套接续流程 |
| Hermes HTTP | 明确传递原生 home/profile、当前模型、provider 和 reasoning；自定义原生目录不会退回默认目录 |
| Claude Code 原生技能模式 | 原生 CLI 接收当前模型、effort、审批及项目 MCP；MCP 经匿名文件描述符传递，凭据不写入命名配置文件 |
| OpenClaw 本地 Gateway | 修正显式状态目录被再次追加 `.openclaw`；保留原生 session key 和原有个人 MCP |
| DSH | 首次打开终端安装固定版本的原生 TUI 插件。保留原来的 ACP profile、原生配置及启动覆盖，只将交互前端换成 TUI；同 ID 恢复原生 JSONL 记录 |
| DeepSeek ACP | 该适配器使用 DSH 原生会话格式，复用 DSH TUI 接续；支持其自定义 sessions root。终端技能加载器绑定实际 DSH 程序，避免因两个入口包不同而漏掉技能筛选 |
| Cursor | 将该会话的 ACP 目录与原生 TUI 目录关联到同一存储，包括 SQLite WAL/SHM。通过已验证的原生 parser 注入项目 MCP，保留个人 MCP。公开消息使用原生 codec 读取，不导出隐藏推理 |
| 探测隔离 | 补齐显式 Cursor 数据根、DeepSeek ACP sessions root、DSH profile 配置；DSH 探测的最终覆盖强制记录写入临时目录，避免用户自定义持久化配置指向日常记录 |

DSH 的终端组件为 MIT 许可的 [dsh-tui](https://github.com/dsh-tui/dsh-tui) `@dsh-tui/dsh-tui@0.1.2`。插件安装在原生 home 下的独立 `kaus-tui` profile；原生插件文件保持不变，版本兼容通过 Kaus 进程加载器完成。未安装 pnpm 时使用 npm 的本地缓存执行固定版本包管理器，不替换用户全局安装。当前验证 DSH `0.1.5-rc.3` 和 DeepSeek ACP `0.9.0`；其他版本需验证相应原生接口。

## 真实模型往返

四条路径分别完成 Kaus → CLI → Kaus → CLI → Kaus，共五轮。测试复用已有账号或连接凭据，项目、技能、会话和原生历史全部在临时目录。

| 路径 | 验收结果 |
| --- | --- |
| Codex | 五轮通过；同一原生 ID；两侧读取项目技能；前文和终端新增内容连续；重复返回不重复回填 |
| Hermes ACP | 五轮通过；同 ID、上下文和项目技能连续；重复返回去重 |
| DSH | 五轮通过；使用已有 DeepSeek 连接进行云端生成；原生 TUI 两次接续，技能内容和前文均保留 |
| DeepSeek ACP → DSH TUI | 五轮通过；同 ID、同原生存储、前文和项目技能连续 |

验证方法：首轮只在用户消息提供随机记忆码，另一个随机码只存在于所选 SKILL.md；CLI 必须回忆首轮记忆并读取技能。回到 Kaus 后，模型还必须回答刚在 CLI 产生的标记。不是以模型自报身份或一次成功退出作为接续证据。

测试暴露并修复了 macOS `/var` 与 `/private/var` 别名引发的工作区误判、DeepSeek ACP 的终端技能加载器目标不一致，以及测试配置副本遗漏组件标记。失败尝试保留在本机，未计为通过。

DSH 完成回复后还复现了一次退出挂起：Python 3.11 的 `asyncio.wait_for` 在读取完成与外部取消同时发生时可能吞掉取消，使历史读取所在的事件任务继续等待。共用只读目录/历史查询已改用 `asyncio.timeout`，保留对子进程的退出清理；回归先在旧代码复现，再在修复后通过。随后 DSH 重新完成五轮真实模型往返及自动退出，没有依靠手动终止取得通过。

## 其他原生组件验收

- Cursor 当前未登录。使用实际安装版本 `2026.09.18` 的 SQLite/protobuf codec，在同一数据库先后写入三阶段消息，读回六条公开消息，消息 ID 稳定，推理内容排除；真实原生 MCP parser 对缺失配置文件、已有个人 MCP 和项目覆盖均通过。**这不是已登录后的真实模型往返验收。**
- DSH / DeepSeek ACP 另外使用真实原生程序与本机模拟模型验证所选技能可见、未选技能不进入模型请求、项目 MCP 工具声明进入三阶段、回填去重和数据库重开。DSH 额外验证自定义 profile、命令覆盖和原生持久化目录；读取器按原生配置合并顺序解析实际目录，不假设记录总在默认位置。无法静态解析的任意 JS 目录表达式会明确要求适配，不执行用户配置代码，也不偷偷读取默认目录。
- 较早一轮共 17 条路径使用真实原生程序、PTY 和本机模拟模型完成往返。包括 Codex、Claude 原生技能模式、Hermes HTTP/ACP、Gemini、OpenCode、Kilo、Qwen、Copilot、OMP、Goose、Grok、Pi、Command Code、Crush、ZCode、OpenClaw 本地 Gateway。该证据不代表这些引擎都完成了真实云账号验收。

## 上游接口限制

| 情况 | 具体边界 | 可实施方案 |
| --- | --- | --- |
| Claude Code 受管技能集合 | 已适配 SDK 可传入精确技能集合；当前已检查的原生 TUI 没有等价的技能目录白名单入口。关闭所有技能或换空 HOME 会破坏用户要求的配置保留 | 此模式继续使用 Kaus；原生 CLI 开放等价入口后接通。另建基于 SDK 的终端是新界面，不标为原生 CLI |
| OpenClaw 远程 / 已有非受管会话 | 远端配置回执和会话所有权不由本地文件目录决定；本地独立 Gateway 的验证不涵盖该情况 | 需要服务端支持对应回执与逐会话范围，按远端版本验证后开放；不修改远端全局身份或权限来替代 |

## 尚未完成的 Kaus 适配

**Antigravity 原生 CLI 往返仍未完成，不列作已交付，也不笼统标为上游不支持。**

本机 ACP `1.1.1` 与原生 `agy` CLI `1.2.7` 使用不同记录根和不同运行入口。已核验两侧 SQLite 表结构相近，但这不足以证明可直接互换：公开消息回填、轨迹关联、CLI 技能选择、项目 MCP 和电脑操作范围还没有形成经过验证的完整桥接。ACP 的 `ANTIGRAVITY_HARNESS_PATH` 配置注入不能直接用于当前 CLI 内嵌运行时。本轮在隔离范围获得 ACP 真实运行记录，用于后续 codec/范围适配；没有把该运行算作 CLI 往返。

这里有两个不同性质的缺口：

- **Kaus 尚未完成**：两种原生记录之间的公开消息读取、轨迹恢复和双向写权交接。CLI 有 `--conversation` 入口，不能把缺少桥接写成“上游没有终端”。
- **当前已核实的原生接口限制**：随 CLI 安装的 `agy-customizations/docs/json_configs.md` 明确说明 `include_only` / `exclude` 不会过滤从用户环境继承的技能。直接添加项目 `skills.json` 不能实现 Kaus 选择集合；切换 HOME 或改写个人技能目录会改变用户原有配置。ACP 的范围代理也不适用于 CLI 内嵌运行时。

[上游的会话导入](https://antigravity.google/docs/cli/commands/resume/)通过复制轨迹创建 CLI 会话，不能直接当作同一份记录的双向接管。接通需要先有 CLI 对全来源技能及 MCP/电脑操作范围的可控接口，再完成原生轨迹桥接与往返验收；另一条路线是基于现有 ACP 做终端界面，但那不属于用户要求的原生 CLI。本次保持入口关闭，不修改个人全局目录。上述结论限于检查过的安装版本，不能外推为未来版本永久不支持。

## 登录和连接条件

- Claude Code、Cursor 本轮原生状态复核为未登录；登录后需要补真实模型往返。Claude 的受管技能限制与登录分开计算。
- DSH 和 DeepSeek ACP 的实测临时复用了已有 Hermes 配置中的 DeepSeek 凭据，没有把密钥写到其他 Agent 的日常配置中。实际使用需在对应原生连接配置该已有密钥。
- Pi、Qwen、Copilot、Grok、Command Code、Kilo、OMP 等尚未具备当前验收需要的独立原生连接；详见 [连接检查](discovery-isolation-20261024.md)。这些不是“适配不支持”。OpenCode 的既有密钥问题也应按原生连接处理。

# 存储与接续交付记录（2026-10-17）

> 当前范围已收束为仅管理 Kaus 发起的对话；外部旧历史关联及独立历史库界面已撤下。以 [对话保存范围](native-archive-storage.md) 为准。以下保留历史交付记录。

后续客户端调整以 [交互补齐记录](interaction-release-20261017.md) 为准。以下验收段保留上一轮记录。

## 当前规则

- 原生 Agent 管理自己的记录位置、清理和账号。Kaus 只读原生历史，不修改保留期限。
- 资料库 → 历史 → 关联历史，选择来源会话和 Project。关联只保存索引；原件变化后读取新内容，已被原生清理的记录不再显示在日常历史列表中。
- 客户端不提供独立归档创建入口。已有保存内容保留读取、导出和恢复。
- Kaus 保存 Project 关系、书签、审批、运行状态和无法从原生记录完整还原的内容。普通对话的新增文字仅在本地原生文件逐字核对通过后替换为引用。已有记录不做追溯压缩或删除。
- 关联列表不为展示状态读取所有正文；分页和附件读取固定当前版本，原件变化时要求重新打开。

现有历史的扫描与 Project 关联支持 Codex、Claude Code 和 Hermes。普通会话的只读本地接口已覆盖 Codex、Claude Code、Gemini、Hermes、Pi、Command Code、Copilot、Qwen、OMP、Goose、Grok、Crush、ZCode。最后是否释放 Kaus 文字副本仍按每次读取的完整度和逐字核对结果决定；Crush/ZCode 当前 reader 报告不完整，继续保留 Kaus 内容。其他引擎在本轮仍使用既有 Kaus 存储，不能将普通会话接口覆盖等同于全引擎原生历史扫描完成。

## 第 5 项：跨 Agent 接续

入口位于原对话菜单「用其他 Agent 接续」及历史阅读页。选择目标 Agent 后，用户审阅并可修改交接内容，选择兼容附件，再创建关联的新会话。应用在同一窗口跳转到新会话，输入框预填交接草稿，发送由用户触发。

原会话引擎和记录保持不变，新会话显示来源名称。目标 Agent 使用当前 Project 下适合自己的配置；原 Agent 的专属技能、隐藏推理、工具进程和认证状态不当作可移植上下文。

新会话所需的全文文件和已选附件仍是实际副本，因此「历史关联不复制」不应被扩写为「跨 Agent 接续也完全不占空间」。后续接续 UX 调整需同时决定这类交接材料的呈现和生命周期。

# Agent 适配补齐与验收（2026-10-17）

本轮补齐项目 MCP 和原生终端接续，并逐项复核专属技能的运行范围。验收使用独立临时 HOME、合成项目/技能、真实安装的 Agent 进程和本地模型/MCP 服务；不读取个人会话、不更换登录、不调用外部模型账户。

正式新增接入保留 20 个 ACP 预设。Alma、Devin 撤出新增接入，已有连接、配置、会话和历史保留兼容。判断依据是 Project 核心技能范围能否真正执行；未登录、缺少原生 TUI 或与其他产品同源都不单独构成撤出理由。Hermes HTTP 另有专属适配。

## 已完成的变化

| 项目 | 已验证的结果 |
| --- | --- |
| Pi / Command Code 项目 MCP | 用原生 extension/mod 注册工具，共用 stdio、HTTP、SSE 客户端；新建、同 ID 冷恢复、更换、清空、失败恢复均验证实际调用结果。原生审批规则继续生效。 |
| Pi / Command Code 终端 | 生产 SessionHost → SurfaceCoordinator → TerminalLauncher → 原生 PTY/TUI → 返回页面 → 同 ID ACP 接续；三个阶段实际执行项目 Skill 和 MCP，当前模型和 effort 传递，公开记录回填且重启不重复。 |
| Command Code 启动 | 修复原生 TUI 早提交时尚未绑定历史和 Mod 的竞态。只调整已核验版本的聊天队列就绪条件，不拦截登录、信任目录或键盘输入。延迟 MCP、提前输入，以及全部移除 MCP 后首屏立即输入均通过真实 PTY 验收。 |
| OpenCode / Kilo 终端 | 原生 attach TUI 使用同一会话与数据库；在技能快捷命令展开前检查项目范围，动态新增的未选技能不能执行；当前模型、运行模式与 effort 进入实际请求。 |
| OpenClaw 项目 MCP | 原生会话覆盖只管理 Kaus 持有的服务；stdio、HTTP、SSE 实际调用、同 ID 更换/清空/失败恢复、两个并行会话隔离均通过。原生全局 MCP 同时可用，配置保持不变。工具标题使用服务名。 |
| Devin 兼容层 MCP | 新建和重新启动时检测原生连接状态；独立命名避免覆盖同名原生服务，独立缓存避免更换/清空后保留旧目录。A→同名 B→清空后，原生 `/mcp` 仅保留用户原有服务。完整工具回合及同 ID 持久化恢复未验收，不据此恢复正式支持。 |
| Alma 兼容层聊天终端 | 原生 TUI 接续同一线程、读取公开历史并使用当前模型；实际官方 TUI 与合成 REST/WS 服务通过。退出时等待原生生成停止；若未确认停止，返回页面后也不能重复发起生成。这不弥补项目 Skill/MCP 缺口，不据此恢复正式支持。 |
| MCP 生命周期 | SDK 原生 stdio、HTTP、SSE 三通道调用与取消验证；失败握手及时终止、子进程回收；配置和凭据不放进命令行或普通错误文案。 |
| MCP 显示 | Pi、Command Code、OpenClaw 的工具与审批标题使用目录名称；调用标识、参数及助手正文保持原样。两家 extension/mod 的原生实际调用与公共事件标题已分别核对。 |
| 共用适配 | 将运行期适配与 Skill 投射分开，不能因为只接入 MCP/终端就声称支持项目 Skill；普通会话和组长继续使用相同驱动。 |
| 立即返回页面 | 修复原生 CLI 退出后 MCP 子进程仍短暂清理、被误判为无法收回终端的竞态；没有进程身份时只等待自然退出，不盲目杀进程。 |
| 启动与取消 | 初始化、原生会话建立前后取消，均关闭尚未登记到运行列表的 ACP 连接；运行钩子异常转为可重试的简短失败状态，不暴露原始路径或凭据。 |

Command Code 的原生 Plan 模式不提供 MCP 执行工具，原生执行模式下可用。Kaus 保持用户所选权限，不为调用 MCP 自动改为完整权限。

## 专属技能边界

正式保留的 20 个 ACP 预设均已有项目技能范围适配。另 2 个预设保留旧连接兼容。Hermes HTTP 另有专属实现。项目树中分配的 Agent 专属技能只进入对应 Agent 的适配器；切换引擎不会把另一家的专属技能交给它。

本轮再次核查两个例外：

- **Devin**：实际版本 3000.11.3，关闭第三方配置导入仍加载自身 user/workspace/builtin 技能。当前没有可核验的逐会话全来源选择入口。需要原生加载层提供清单/回执，或可维护的加载层适配；换 HOME 不能消除内置来源。
- **Alma**：实际 Mac 0.4.148 中，thread 的技能列表和 workspace allowlist 都不能阻止全局 always-inject 技能；原生 Skill 工具还可能访问全局技能。项目专属技能必须有完整 thread/workspace 范围接口，或独立服务实例。不能用修改用户全局配置替代项目隔离。

两家旧会话继续兼容；新接入、新会话及组长新选项不再提供这两个预设。恢复正式接入前，必须补齐已列出的核心范围缺口。

Alma 不再作为正式新增接入，也不默认附带额外服务或容器。实际 0.4.148 插件目录和 ToolSearch 都是全局集合，插件执行回调的 threadId 为空，轻量插件不足以实现项目范围。独立实例还需解决多 Project 配置、内置来源、升级、凭据、端口和资源管理，不能将它当作一次简单安装。此取舍依据产品一致性与维护成本，不取决于某位用户是否使用 Alma。详见 `devin-alma-completion-20261017.md`。

## 原生终端仍受限的项目

| Agent | 已确定原因 | 具体解决路径 |
| --- | --- | --- |
| Claude Code | SDK 的 `initialize.skills` 有选择范围；核查 2.1.228 / SDK 捆绑 2.1.300 的交互 CLI，没有等价选择入口。仅关闭所有技能不能满足保留项目所选技能。 | 继续通过已适配 SDK 在 Kaus 使用。要提供相同受管终端，需要基于 SDK 的交互终端或原生 CLI 等价接口；不能靠普通 `--resume` 完成。 |
| Antigravity | 已验证的 ACP/harness 1.1.1 和本机交互 CLI 1.2.7 是不同执行入口，原生轨迹分别位于 ACP/CLI 目录；现有范围守卫只作用于 ACP harness。 | 需要同一轨迹的 CLI 导入/返回契约、CLI 等价范围控制和当前配置映射；不能移动/覆盖个人原生目录假装原位恢复。现有 ACP 技能及 MCP 已验证，不影响 Kaus 内对话。 |
| Cursor | 原生 `--resume` 存在，但当前会话创建要求认证；尚不能完成同 ID 生成、原生历史和 MCP 冷恢复的实际验收。 | 用户登录后，用临时会话补真实链路；不会把“存在 resume 参数”当作终端接管完成。 |
| DeepSeek ACP | 原生程序明确是编辑器使用的 stdio 协议服务，没有面向人的 TUI。 | 使用 Kaus 对话；若产品需要独立终端，可开发共用 ACP 终端客户端。 |
| DSH | 本机 0.1.5-rc.3 安装包有 web/headless，帮助中的 tui 示例要求用户另装对应 profile。 | 提供可运行且支持恢复的 TUI profile 后，再适配原生终端；当前不把 headless 程序伪装成交互终端。 |
| Devin | 无已验证的持久化空会话/原生终端恢复契约；受管技能仍有上述加载范围缺口。 | 在原生模式完成可持久化会话后确认历史/恢复协议；受管终端还必须补全技能范围。 |
| Alma 工具终端 | 原生 TUI 没有完整工具审批/交互请求通道；聊天终端已适配，实际本地服务与模型还未验收。 | 工具任务继续在 Kaus；增加终端审批通道后再开放工具模式。账号验证不能代替审批通道。 |

OpenClaw 目前验证的是本机 Gateway。远程服务返回脱敏凭据时，缺少可信配置回执，不能验证下发值；需要远程会话配置回执或受控服务端适配。已有非 Kaus 管理的原生会话保留原身份，要使用受管 Agent 范围需新建 Kaus 会话。

## 登录、外部服务与版本

登录由用户在各引擎原生入口处理。只有 Cursor 的本轮真实会话验证被明确的认证错误阻断；其他引擎使用隔离 loopback 完成的测试不等同于声称真实账号已登录。远程 MCP OAuth、企业策略、收费模型与完整业务任务需要对应账号，但本轮可在本机验证的配置、工具执行、取消和进程生命周期已经单独检查。

部分专属范围适配依赖精确原生版本或模块指纹。未知升级需要重新核验接口，普通原生接入与受管项目范围应分别判断。

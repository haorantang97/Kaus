# Project 指令：默认生效（设计稿）

2026-11-01 草稿，已由 [Project 配置通用化](project-config-generalization-20261102.md) 取代。

## 现状

Project 指令就是各 Agent 读的 `AGENTS.md` / `CLAUDE.md` 一类内容。Kaus 里现在有两套：

| | 编辑位置 | 怎么到 Agent | 覆盖 |
| --- | --- | --- | --- |
| Hermes 守则 | 项目页「指令与守则」 | 保存时、后台监听和启动时自动写进每个 Hermes 档案 `SOUL.md` 顶部的托管段 | 只有 Hermes |
| 通用指令 | 没有编辑界面；只有 Hermes 人设会被镜像成一条 | 只有手动点「应用项目配置」，才写进工作目录里该 Agent 读的文件（Claude 是 `CLAUDE.md`，Codex/OpenCode 是 `AGENTS.md`，Gemini 是 `GEMINI.md`，Qwen 是 `QWEN.md`） | 其他 Agent |

所以「未生效」的原因是：除 Hermes 外，指令只在手动应用后才进文件；没设工作目录、或该 Agent 没有约定的指令文件，就永远进不去。批次 44 当时故意做成手动：怕改坏用户仓库里的文件，且各 Agent 的文件名没实测。之前修过的 CLAUDE.md 问题是「每个 Agent 用各自的文件名、托管段用各种 Markdown 都认的注释格式」，没有改成自动。

## 概念

- **工作目录**：Project 对应的那个文件夹，Agent 在里面读写代码、读 `AGENTS.md`。在输入框旁的文件夹按钮设置。没设时 Agent 在 Kaus 自己的目录里启动，指令无处可写。
- **托管段**：Kaus 只改文件里一段带注释标记的内容，标记外的文字不动。
- 为什么不直接覆盖整个文件：工作目录里的 `AGENTS.md` 常常随仓库提交、团队共用，也可能由别的工具写入。两边都是你写的，但归属不同：文件属于这个仓库，托管段属于这个 Project 在 Kaus 里的配置。整篇覆盖会把仓库原有内容和别人的改动一起抹掉。

## 方案

1. **一个编辑器**：项目页只保留一个「Project 指令」，按树继承（上级 + 本级，下级可屏蔽或改写上级某一段）。Hermes 守则并进来，不再单独维护人设镜像。
2. **每次开对话前自动生效**，按 Agent 选最稳的通道：
   1. Agent 有启动时附加提示的接口，就从这里注入，不碰文件。仓库里已经用过的有：Claude 的 SDK `systemPrompt` 附加，Codex 的 `developer_instructions` 配置。
   2. 没有，就自动更新工作目录里该 Agent 指令文件的托管段，标记外的文字不动。同一文件夹里有别的对话正在运行时，等它结束再写，或者本次照旧并提示。
   3. 两者都没有（目前 antigravity、openclaw、pi、hermes-acp、dsh、deepseek-acp、kilo 没有约定的文件），逐个确认它们的启动参数后再接入，这之前保留「未生效」提示。
3. **没有工作目录的 Project 先选目录**：开第一个对话时就要求选，不再静默在 Kaus 目录里跑。
4. **接入已有的 Agent / 文件夹时导入一次**：发现工作目录里已有 `AGENTS.md` 或 `CLAUDE.md`，给你两个选择：
   - 「导入为 Project 指令」：内容进 Kaus 编辑器，原文件里这部分换成托管段，以后在 Kaus 里改；
   - 「保留原文件」：不导入，Kaus 的指令只写在托管段里，和原文共存。
   这样已有的配置不用重写，可以在原有基础上改。
5. **文件里被手动改过**：项目页标出「文件中有改动」，选「采用文件里的」或「用 Kaus 的覆盖」，不自动二选一。

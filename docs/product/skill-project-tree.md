# Project 技能树

确认日期：2026-10-15。

Project 仍是唯一的配置层级。项目下直接显示通用技能，随后显示默认折叠的 Agent 专属技能分组。分组只是视图，不拥有独立配置、继承或项目树。

每项技能分别记录资源身份、来源 Agent 和项目分配。同名技能不合并；移动项目归属不改变 Agent 适用范围。配置先使用现有 Project resolver 计算继承、覆盖和阻断，再由适配层按 Agent 选取。

## 操作

- 拖动和菜单具有同等地位，调用同一写入接口。
- 项目行和折叠分组接收拖放；悬停展开。拖到技能行显示前后排序落点。
- 跨项目移动保留 Agent 归属，自动进入目标项目的对应分组。
- 继承项显示来源。移动来源赋值前展示受影响项目；不会把继承副本误当成本地文件移动。
- “另加到”创建分配引用。技能内容文件仍保留原位置。
- 停用从当前项目向下传播；恢复继承撤销本层阻断。
- 操作按 revision 检查并发更新，并提供一次撤销。页面刷新不重新导入已移动或已移除的原分配。
- 搜索可以展开并定位折叠的专属技能。空分组隐藏。

## 本轮边界

本轮实现技能发现、持久化编排和配置解析，以及对应界面。原生技能扫描只读，不搬动安装目录，不启动模型。

原生引擎实际加载和完整隔离的验收由用户明确延后。Hermes 独立项目执行目录补充按项投射；原生目录连接和通用 ACP 的加载适配仍有缺口。不能把界面分组、resolver 或临时文件测试记作运行隔离通过。具体待办见 [运行隔离验收](skill-runtime-isolation.md)。

## 后续讨论：Agent 接入与数据归属

待用户继续讨论后确定，不在本轮改动：

1. 已知路径轻量发现、手动确认接入与首次选择自动接入的关系；已发现、已接入、已登录、可启动状态的呈现。
2. Kaus 独立保存完整用户可见记录和媒体资产。现有存储按 driver 的 history 能力分别保留原生历史或本地内容事件；并非统一独立档案。
3. `artifact.created` 的长期保留、远程/临时 URI 资产归档、历史能力读取失败时的保留策略。
4. 跨 Agent 继续采用保留原会话的分支/移交，区别文本上下文、文件与原生工具状态；不改变现有会话的引擎身份。

以上是待讨论事项，不是已实现承诺。

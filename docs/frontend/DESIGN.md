## ★ 定稿裁决（2026-09-03 起，Fable 亲自定，用户复核通过）——本节优先于下文全部内容

用户对现有界面的字体、布局、图标与小元素**整体满意**，明确要求**不要大改**。因此本文下面各节（第 0–13 节，批次七 a 子代理的初稿）降级为**现状体检与参考资料**：凡与本节冲突的，以本节为准；本节没提到的，一律**保持现状不动**。

### A. 视觉：只改两处颜色

| 项 | 现状 | 定稿 | 理由 |
|---|---|---|---|
| 深色模式强调色 | `--gold: #cbee52` / `--gold-deep: #a7c93a`（青柠） | **`#8FCDBB`**（主）/ `#6FB3A0`（deep，用于线条与边） | 青柠在深底上把侧栏与图谱压得看不清（用户实测反馈） |
| 浅色模式强调色 | `--gold: #c4ee45` / `--gold-deep: #7f9a22` | **色相不变**：色块、chip 底、连线、选中条照旧用现值；**只有当它作为文字时**（"继承自 X"这类绿色小字、链接）改用 `#5E7A12`（同色相压深，对比度 2.59 → 5.1） | 用户要求保留现有浅绿；文字档太浅是可读性问题不是审美问题 |

变量名保留 `--gold*`（不改名，避免 117 处引用大改）；新增两个变量 `--accent-text-light: #5E7A12`、`--accent-dark: #8FCDBB`，由 `theme-overrides.css` 的深色块覆盖 `--gold`/`--gold-deep`。**首页 hero 深色块、Anton 展示体、Space Mono、现有圆角与间距全部保留**——第 3.4、4.2、5.1 节的"取消 / 归并 / 拆四种"建议**不执行**。

引擎不分配颜色（第 2.4 节）**保留为规则**：这是给以后接第二个引擎用的，不影响现在。

### B. 侧栏 = 会话列表（不是项目树）

- 顶部常驻 **「+ 新会话」**；下方按项目分组列会话，运行中置顶，组可折叠；项目本身不进侧栏。
- **概览页**（= 现有轮盘图谱，作为首页保留）侧栏默认收起，鼠标贴左边缘悬停滑出；一个图钉可钉住常驻。进入会话/项目页后侧栏常驻。
- 现有 `Sidebar.tsx` 的紧凑树**不删**，改为项目页里的次级导航（信息架构文档同步改，未决问题 2/3 按此定）。

### C. 「+ 新会话」= 全屏草稿页（参照 Claude / Codex 的新对话）

- 点击后右侧整屏是一个**居中的空对话窗口**（草稿态），**侧栏不 +1**；第一条消息真正发出后，会话才建立并进入侧栏。
- 草稿页的空白区域放配置：**所属项目**（默认 = 设置里的"默认去向"，初始为根项目 X）、**引擎**（该项目已接的引擎，切换即换 Binding）、**模型 / 推理强度**（随引擎变化，读该 Binding 的模型目录）。三者都是下拉，改了立刻生效，不弹二次确认。
- 从项目页点「新会话」进入同一个草稿页，只是项目预填且默认不可改（可解锁）。
- 草稿页离开不保存（没有发出的消息就没有会话）。输入框里的文字在本次页面会话内保留（sessionStorage），刷新即丢。

### D. 轮盘图谱：只做手感与 bug 修，不重写

用户多次迭代过这套轮盘，**阻力手感要保留**（`delta × 0.0018`、`spring = 1 − e^(−dt/86)` 两个常数不动）。"不够丝滑"的根因在实现而不在参数，修这三处：

1. **滚动中不要提交选中。** 现在每个滚轮事件里 `round(target)` 一变就 `commitWheelSelection` → `setSel/setPath` → React 重渲染 → `useLayoutEffect` 里 `alignWheelToPath` 又把 `target` 拽回去，和用户的滚动打架，这就是卡顿的来源。改为：滚动中只更新 `state.current/target` 和高亮预览（`current-front` 类），**只在吸附定时器（110ms 无输入）到期后**提交一次选中。
2. **动画帧里不重算连线。** `redraw()` 每帧对每个节点做 `getBoundingClientRect` 并重写整段 SVG `innerHTML`，是布局抖动。动画中调用 `redraw(true)`（只更新 transform），静止后（吸附完成）画一次连线；窗口 resize 照旧全画。
3. **去掉远端节点的 `filter: blur`**（`rank > 2.6` 那一档），改用 opacity 表达深度；给 `.ag-node` 加 `will-change: transform`。blur 在合成层上每帧重绘，是掉帧的第二来源。

验收：触控板连续滚动 3 秒无跳帧（Chrome Performance 面板 ≥ 55 fps）；松手后 ≤ 200ms 吸附到最近节点；点击节点、方向键行为与现在一致；`prefers-reduced-motion` 下吸附不做过渡。

### E. 关于"共享 API key / OAuth"

用户提出：多引擎不该反复登录、反复配 key。分两半回答：
- **API key：能做，而且已经在计划里。** 这就是 Phase 5 的"凭据引用制"（AD-48、基线 §5.4）：key 只在 Kaus 的凭据库存一份，每个引擎的驱动把它投影成该引擎认的形式（Hermes 的 `providers`、Codex 的 env、Claude Code 的 settings）。同一家 provider 的 key 配一次，所有引擎都拿到。
- **OAuth 登录：大多数情况不能共享，也不该共享。** 各家 CLI 的 OAuth token 绑定各自的产品与服务条款（Claude Code 的登录态不能拿去给 Hermes 用），技术上也是各存各的。Kaus 能做的是：在"已接引擎"面板里显示每个引擎的登录状态、给一个"去登录"按钮拉起它自己的登录流程；引擎明确允许复用同一凭据的情况（同一家 provider 的 API key）走上面那条。

### F. 对话卡片语法与新页面

新做的页面（草稿页、对话页、项目详情页的"已接引擎"面板、Group 浮窗）沿用现有视觉语汇：现有 `ui.tsx` 的 Card / Pill / Button / FieldRow，现有字体与圆角。第 6 节的卡片语法（工具卡输出栏可缺席、审批卡边框加重不换底色、出错卡左侧细竖条、推理默认折叠）**采纳**，但用现有 token 实现。

### G. 会话页版式定稿（2026-09-03，真机看过 Hermes 一次工具调用后改判）

参照 Claude / Codex / OpenCode 桌面端的共同做法，会话页从"满宽卡片流"改为"居中阅读栏"。字体、颜色、圆角、图标不动（AD-78），只改版式与信息层级。

1. **居中一栏。** 消息流与输入框同宽，`max-width: 760px`，居中；窄于 1100px 时左右各留 24px。页头（标题 / 引擎 / 状态）与这一栏对齐，不再横跨整屏。
2. **助手回复不装盒子。** 助手正文直接以段落渲染（现有正文字号、行高 1.6），左侧不要卡片边框与底色；`Reply` 表头、时间戳去掉——时间只在悬停整条消息时于右侧淡出显示。用户消息保留浅底圆角气泡但去掉 `YOU` 标签，靠右、最大宽 80%。
3. **工具调用 = 一行可折叠。** 默认折叠成一行：`▸ terminal · pwd + 1 command · 1.2s`（图标 + 工具名 + 预览串 + 耗时 / 状态点），点击展开才显示入参与输出；出错时状态点用 `--danger`，行文字不变色。连续多次工具调用合并为一组，组头写"运行了 3 个工具"，展开后逐行。**任何情况下不得把原始 JSON 摆在折叠态。**
4. **推理 = 一行可折叠。** `▸ 思考了 4s`，展开显示推理文本；运行中显示 `● 正在思考…`（现有 pulse 动画）。
5. **审批卡是唯一常展开的卡**：边框加重（F 已定），按钮在卡内右下，回答后收成一行 `✓ 已允许 · terminal`。
6. **运行中的反馈。** 运行时消息流末尾有一行 `● Hermes 正在回复…`（引擎名走现有 displayName），流式文本边到边渲染；输入框右侧的「发送」在运行中变成「停止」（`interrupt` 能力缺失则不显示停止，按 AD-71 静默）。
7. **输入框底部一条工具栏**（左到右）：项目名 · 引擎 · 模型 · 审批模式，各为现有 Pill 形态；能切换的（`models.mode !== "fixed"`、审批模式能力可写）渲染成下拉，否则只读；缺能力的项不渲染。快捷键提示 `Enter 发送 · Shift+Enter 换行` 只在输入框为空时作占位文字出现。
8. **用量不常显。** 现有 UsageBar 从消息流上方挪到页头右侧，折成一枚小 Pill（`30.7k`），悬停展开 in / out / total。
9. **自动跟随。** 新消息到达且用户在底部附近时自动滚到底；用户上翻后不打扰，底部出现现有 Pill 样式的「回到最新 ↓」。
10. **空会话与首屏。** 刷新后从 `?after=` 续上时不闪烁，历史加载完成前显示三行骨架（现有 `AsyncState`）。

### H. 工作区配色收敛（2026-09-03，用户上手后改判）

强调色（浅色 lime / 深色 `#8FCDBB`）适合外壳与概览这类"门面"，放进长期盯着的会话工作区就显得轻浮。规则：

1. **会话页与草稿页里，强调色只剩两处**：运行中的状态点、审批卡的加重边框。其余一律中性。
2. **用户气泡**改用中性浅面（现有 `--surface-2` / 深色对应 token），不再是绿底；边框 1px 现有 hairline。
3. **主按钮（发送 / 停止）**用与导航选中项相同的"深底反白"（深色模式反过来），不用绿底。停止在悬停时才带 `--danger` 边框。
4. **输入框工具栏的 Pill**（项目 / 工作目录 / 引擎 / 模型 / 推理强度 / 审批模式）全部中性描边 Pill，可点的带 `▾`；引擎 Pill 不再用绿字。
5. 页头引擎 chip、用量 Pill、"回到最新"同样中性。
6. 概览页、轮盘、侧栏选中项**保持现状**——门面可以有个性，工作区要安静。

### I. 输入区必备项（对标 Claude / Codex / OpenCode 桌面端）

输入框下方一行，左起：**工作目录**（显示末两级路径，点开可改，写 `PATCH /api/projects/{id}`）· **引擎** · **模型 ▾**（只列该引擎实际可用的模型；目录 `degraded` 时在下拉底部一行小字说明来源）· **推理强度 ▾**（该模型有 `reasoningLevels` 才出现）· **审批模式 ▾**（每次询问 / 自动放行 / 全部放行）；右侧：**附件 📎**（引擎声明 `attachments` 能力才出现）· 发送/停止。每个取值旁若来源不是本会话/本绑定，悬停显示"来自引擎配置"。缺能力的项不渲染（AD-71）。

**I-2 模型下拉只列本引擎的目录（2026-09-05，batch27 热修，真机 D4）。** 真机上这枚下拉里混着别的引擎的模型。数据源本来就该是**该 Binding 的 Model Catalog**（`GET /api/backends/{id}/models?binding=`）而不是任何全局模型表，所以实现上把"这份目录属于谁"判清楚，判断收在 `web/src/lib/modelCatalogView.ts` 一处：① 换会话（常常也换引擎）时**先把上一份目录扔掉**，再按新 Binding 取——否则新目录回来之前列的是上一台引擎的模型，而能力矩阵是 `models.mode === "fixed"` 的那一支干脆不发请求，旧目录会一直挂着；② 目录的 `bindingId` 与当前 Binding 对不上就当**没有目录**；③ 目录条目自带 `backendId` 时按它过滤，没标注的留着（多数目录本来就只有自己的模型，一律丢掉会让下拉空掉）。**没有目录**（端点不在 / 这次没取着 / 那份不是本 Binding 的）时模型那一枚退成**只读的当前模型一项**；**空目录仍然不等于没有目录**（批次十五第 5 件）：菜单照旧点得开，里面写「引擎未报告可用模型」。

**I-3 模型下拉按 provider 分组（2026-09-05，批次二十九，真机 D4 / AD-117 定案）。** 网关型引擎一次报出 47 个跨 provider 的模型，平铺一列读成「混列」：菜单按 `providerLabel` 出**小号大写的中性组头**（与站内其它 section 标签同形，★H 不上强调色），**引擎当前的 provider 排第一**（后端按 `isCurrentProvider` 排好，前端不重排），过滤跨组匹配 id 与显示名、筛空的组连组头一起不渲染（AD-71），**只有一个 provider 或后端没给 `providerLabel` 时不出任何组头**（一个组的分组是噪音）；未登录的 provider 由后端整条丢掉，下拉里只剩这台引擎真能用的模型。

**I-3 追加（2026-09-05，批次三十，真机 P2）。** 分了组仍旧太长——47 条平铺出来要滚很久。所以**默认只展开引擎此刻在用的那家 provider**，其余每组折成一行「组头 · N 个模型」，点组头展开 / 收起；**一开始筛就全部展开**（这时用户要的是「哪儿有命中」，折叠只会把答案藏起来），清掉筛词回到默认那一档。哪家是「当前」由后端的 `isCurrentProvider` 说了算（缺这个键时退回「选中项所在的组」，再退回第一组）。**什么都不持久化**：关掉菜单就忘，下次打开又是同一份默认——记住上次折了哪几组，等于让同一枚下拉每次长得不一样。组头的形态一个字不改（小号大写中性小字），只是点得动。

### J. Group 浮窗（临时协作组外壳，2026-09-05）

右下角常驻一枚中性 Pill「协作组 · N」（N = 开着的组数；0 时只显示「协作组」）。点开是一个固定在右下、宽 420px、最高 60vh 的浮层（不是抽屉、不占主区）；可最小化回 Pill、可关闭。浮层内：组列表（标题 · 成员数 · 状态点）→ 点组展开成员行：会话标题 · 项目 · 引擎 · 运行点 · 表面（终端图标）· 「…」（暂停 / 恢复 / 移出 / 提升为普通会话）。组头两枚动作：「添加成员 ▾」（两条路：**选择已有会话**——弹当前项目下会话的 BarMenu 可搜索；**启动新成员**——项目 / 引擎 / 模型 / 首句的小表单）、「关闭组」（弹处置选择：保留 / 归档，说明各 retention 的后果）。「新建组」在浮层顶部。侧栏会话行属于开着的组时右侧一枚中性小图标（lucide `Users`），悬停显示组名。全部中性配色（★H），强调色只给运行点。开/最小化状态记 sessionStorage；组列表变更靠 `/api/groups/events` 推送刷新，断线重取。

**J-2 展开态 = 三栏（2026-09-05，批次二十六）。** 组一展开，浮层从 420px 变到 **760px / 最高 72vh**，里面是三栏：**成员**（216px）· **组时间线**（自适应，主角）· **Context Packet**（232px），底部横跨一条**广播输入框**。这一片必须读起来像**一件工具**，不是三个并排的小部件——所以：栏与栏之间只有一条 1px 细线，**没有**各自的卡片壳、圆角与底色；三个栏头是与浮层头同一档的 9.6px 等宽大写小字；输入框与三栏共用一条上边线。窄于 820px 时折成三个 tab（纯 CSS，DOM 一个不少）。

- **左栏（成员）**：每行 = 目标勾选框 · 运行点 · 会话标题 · 角色/状态小标 · 项目 · 引擎 · 终端图标 · 「…」。「…」菜单在原来四条之上多一条 **定向发送**（只给 active 的人）。勾选框只出现在 active 成员上——勾一个暂停中的人只会换来一条 `skipped_paused`。
- **中栏（组时间线）**：`messages` **正序**（最早在上、最新在下，与会话页一致；2026-09-14 批次四十五 c 改口径——批次二十六定倒序时这里还只是「用户广播 + 系统事件」的**账本**，倒着读像读一份回执清单，四十五 a/b 之后成员发言、轮次、最终答复都进了这条线，它成了一间**房间**，房间倒着读是反的。贴底与翻旧的规则见 **★J-6**）。每条一行种类小标（广播/定向/系统）· 时间 · 投递摘要「3 已发 · 1 已跳过」，点摘要展开每成员状态。两档 `skipped_*` 在摘要里合成一个数，展开才分得清是"暂停中"还是"已移出"。**失败是唯一染色的一档**（`--danger`）：跳过不是错误，不该红。投递行上后端给了 `reason` 码就按码查文案（`turn_already_running` = 「上一轮还在运行，等它结束再发」），查不到才用后端的 `detail` 原文（batch27）。时间线**最上面**还放**常驻通知**：spawn 的首句没发出去时是一条不会自己消失的红边通知（点名是哪条会话 · 后端的原因 · `hint`），成员行上同时一枚小标——这类回执此前是 toast，紧跟着的「已添加」把它盖掉了，真机上用户看到的是"成功"（batch27，真机 ①）。组一关，侧栏那枚组名小标**立刻**消失（共享 store 当下就把它抹掉，并催会话索引重取一次；索引行是 30s 一轮的缓存，等它自己更新就是真机 C5 的残留）。
- **右栏（Context Packet）**：只读表（成员 · 引擎/模型 · 状态 · 最近一句）+ 「复制 Markdown」+ 「刷新」。它是**现算的一份快照**，所以不跟着推送重算，只跟「刷新」。可选键拿不到时那一格**是空的**——不写「未知」（AD-71）。
- **广播输入框**：与会话页 ComposerBar 同一视觉语汇（中性描边、`.kaus-send` 的深底反白主按钮），但**矮一档**，没有那一整行工具栏。默认发给全部 active 成员；勾选缩小目标时头上一句「只发给勾选的 N 名成员」，「定向发送」时是「定向发给「X」」加一枚「取消定向」。发出去的那条**先以「发送中」进时间线**，`deliveries` 回来后**整条替换**成后端那份；失败就地标成「没发出去：…」并把原文留着。组关了（`status` 不是 `active|minimized`，或后端回 409 `group_closed`）**输入框整个不渲染**，位置上是一句「这个组已经关闭，不能再发消息」——不让人打完字再吃一个 409。

**J-3 「接入引擎」面板（2026-09-05，批次二十六）。** 项目页引擎区**右上角**一枚中性按钮「接入引擎…」，点开是 720px 的弹窗：左列八个预设（Claude Code / Codex / OpenCode / Gemini CLI / Qwen Code / OpenClaw / Pi / Hermes (ACP)，选中态是中性描边加重），右侧是**可直接粘的一行配置**（等宽，`id` / `driver` / `preset`，要 key 的多一行 `env_keys`）+ 「复制配置」+ 登录方式一句话 + `env_keys` 提示 + 一句固定的「改完 `dashboard-config.json` 要重启后端」。**它不请求后端**（这时后端当然还不认识这个引擎），也**不代写配置**（那是用户的文件）。内容与 `docs/ops/backends.md` §4 同源。引擎卡上：行里带 `preset` 时卡头多一枚只读小标（`preset.label`），能力清单区多一行「预设：<label>」；**`quirks` 那七位布尔一个字都不显示**——它们是 Driver 的分支开关，不是能力（AD-71）。

**J-4 拖拽入组（2026-09-13，批次四十二）。** 架构 v1.2 §路径 A 的「拖入 Group」是锁定需求，此前只做了下拉。

- **拖源**：侧栏每一条会话行。`dataTransfer` 上写 `application/x-kaus-conversation`（值 = 会话 id）并顺手带一份 `text/plain` 的标题（回执要点名）；`effectAllowed = "link"`。行内按钮上起拖 `preventDefault`（否则点开一个菜单再一拖就把整行拖走了）。拖动中整行压淡（`.is-dragging`，opacity 0.45）——不发明新形状。
- **放置目标**（同一套逻辑，`lib/groupDrop.ts` 的 `useConversationDrop`）：① 收起态的浮窗胶囊；② 展开态的成员栏——它同时**就是**组工作区的那一栏（`GroupWorkspace` 把它原样摆在三栏第一栏），所以一处即覆盖两处。`dragover` 只认上面那个 MIME：认了才 `preventDefault` 并加 `.is-drop-target`（**2px `--k-accent` 虚线框**，§5.9 的老规矩，实现令牌是 `--gold`），`dragleave` / `drop` 去掉；别的拖拽连框都不给。
- **drop 的动作**与「选择已有会话」是**同一条调用**（`POST /groups/{id}/members`）。成功 → 成员列表刷新 + 一句「已加入 <标题>」；失败仍旧按 **code** 翻人话（表外的 code 用后端原文）。**不做项目限制**。
- **拖一个项目 = 路径 B「启动新成员」**（2026-09-13，批次四十三；用户裁决同日）。组成员只能是会话（v1.2），所以「把项目拖到组上」**不是新设计**，而是浮窗里那条「添加成员 ▾ → 启动新成员」的拖拽入口：从那个项目的**默认引擎**起一条新会话加入组。拖源是侧栏的**项目分组表头**与轮盘上的**项目节点**；MIME 用另一个（`application/x-kaus-project`，值 = project id 或轮盘那头的裸名字，放置端过一遍 `matchProjectId` 统一），`text/plain` 仍旧带显示名。**两种拖拽互不误触发**：判 kind 只看 MIME，不看值的形状；轮盘上拖到**别的项目节点**上仍是改父级（那条路只看它自己的 React state，一个字没动）。drop 的调用是 `POST /groups/{id}/spawn`，**只带 `projectId`**——binding 不传（用默认绑定，没有就让后端的 `binding_required` 说话），首句不传（拖拽没地方打字，不替用户编一句）。成功「已从 <项目名> 启动一名成员」，失败仍旧按 code 翻人话。胶囊上的组选择规则（①②③④）原样适用，不因拖的是项目而变。拖拽本身看不见，所以侧栏项目表头悬停时有一句话把它说出来。

- **胶囊上 drop 加入哪个组**（2026-09-13 修订——用户真机第一次试拖就卡住：刚刷新的页面没有"当前组"，拖过去一点反应都没有）：① 浮窗记着当前组 → 加入它；② 没有当前组但只开着一个组 → 就是它，不让人选；③ 没有当前组且开着多个 → 打开浮窗、摊开第一个组，提示「拖到具体那个组的成员栏上」，**不替用户猜**；④ 一个组都没有 → 提示先建组，且不加虚线框（AD-71）。原则：②③必须有反馈——**静默是最坏的结果**。

**J-5 成员的回复进这条时间线（2026-09-14，批次四十五 a；PRD §B2）。** 此前组时间线上只有用户说过的话——成员答了什么，组自己不知道（`author_type="member"` 的位置留着没人写）。现在成员每答完一轮，时间线上多一条 `kind="member_turn"`。

- **它与用户那几条是同一条时间线、两种读法。** 用户的行第一眼看「发给了谁、送到没有」（投递摘要）；成员的行第一眼看「**谁说的 · 哪台引擎 · 跑了几个工具**」——成员发言压根没有投递，那枚摘要按钮整个不出现（AD-71）。
- **形状上只差一条竖线。** 不给它卡片壳、圆角或底色（★J-2 的老规矩：这一片要读起来像一件工具）；区别只靠左边一条 2px 的中性细竖线 + 8px 缩进，顺着往下扫时「这是别人说的」一眼分得出来，又不必先读完一枚种类小标。种类小标因此**不出现在成员气泡上**（词典键留着给兜底）。
- **失败仍是唯一染色的一档**（★J-2）：`outcome=failed` 把那条竖线换成 `--danger` 的淡色 + 一枚红字小标；`interrupted` 只是一枚灰字小标——被打断不是错误。
- **三档静默**（AD-71）：`toolCount` 为 0 不写「跑了 0 个工具」；引擎取不到不出那一格；正常结束不写任何状态词。工具**只给数**——一个工具名、一个入参都不进这条时间线，那些属于成员自己那条会话的页面（PRD §B8 L1）。
- **正文可以是空的**：失败 / 中断那一轮引擎可能一个字都没说完，后端不编一句「（失败）」，界面也不留一片空白，写一行灰字「这一轮没有留下正文。」。超过 4000 字被截时正文下面一枚小标说明只留了前 4000 字。
- **成员名的口径与发给引擎的那张名片是同一份**（`roleLabel` > 会话标题 > 成员 id 尾段，见 `app/collaboration/room.py`）。必须一样：界面上叫「写手」而引擎被告知自己叫「会话 3」的话，用户读同一条时间线会读出两个人来。重名后缀（`#2`）这一版由后端那张表定，前端不再算一遍。
- **不做「转给…」按钮**（那是 §B4 / 批次四十五 b）。

**J-6 正序、贴底、翻旧（2026-09-14，批次四十五 c；用户真机反馈）。** 中栏一改正序，就有两个此前不存在的问题：新的一条来了要不要跟着滚下去，以及怎么往回翻到组刚建的时候。

- **顺序**：最早在上、最新在下。后端 `GET /groups/{id}/messages` 仍旧给「最近 N 条、**倒序**」——那是 wire 的分页口径，翻面在前端做，接口一个字不动。**乐观占位排在最底下**（正序里「正在发的那一条」就是最新的一条），后端回来的那条也接在最后。
- **贴底**：新条目到达时，用户本来就在底部（**距底 ≤ 40px**，一行的余地）→ 自动滚到底；用户往上翻了 → **一个像素都不动**，改在时间线**底部**露一枚 sticky 的「回到最新 · N 条新」，点它滚到底。自动滚一个正在读旧内容的人的视口，比「新消息看不见」更糟。首次加载完滚到底；用户自己刚发了一句也贴回底部（他一定要看见自己说的话）。
- **「N 条新」按序号数**，不按列表长度差：往回翻旧也会把列表撑长，长度差会把「翻旧」数成「来了 50 条新的」。用户每次回到底部就把「读到的最大序号」记一次。
- **翻旧**：时间线**顶部**一枚「加载更早」，用 `nextBefore` 当 `?before=` 游标；`nextBefore` 为 `null` = 已经到组刚建的时候，那时这枚**整个不渲染**（AD-71：不给一枚按了没反应的按钮）。点了把更早的一页**前插**，插入前记下 `scrollHeight`、插完把长出来的那一段加回 `scrollTop`——用户眼前那一行停在原处，不跳。前插**不算**「新内容」：不计数、不贴底。
- **常驻通知仍在最上面**（★J-2）：它是通知，不是消息，不参与这条时间线的排序。组头那行「第 k/N 轮 · 轮到 B」+「停」位置不变。
- **判定全是纯函数**（`shouldStickToBottom(scrollTop, scrollHeight, clientHeight)` / `maxSequence` / `unseenCount`）：jsdom 没有真实布局（两个高度恒为 0），所以像素那一层一个字都不测，只测这三个函数、顺序，以及按钮的出现/消失。
- **翻到头那一下按钮就没了**（2026-09-21，批次五十二，真机 UI-04）：后端在**本页最早那一行的 sequence 为 0** 时就把 `nextBefore` 给成 `null`（组内 sequence 从 0 起，这是精确判据），所以「加载更早」在看见第一行的**同一屏**里消失，不必再点一次拿回一页空的。前端这一处一个字没改——判据本来就该由出数的那一头给。

**J-7 名字是一等公民（2026-09-21，批次五十二；真机第三次外派）。** 这一片里「他叫什么」出现在**六处**：成员栏、时间线气泡、投递明细、组头「轮到 X」、勾选框的可访问名、Context Packet 那张表——外加引擎那边的房间说明。它们必须是**同一个名字**，因为显示名同时是**称呼**与**地址**（`@名字` 要解析回成员 id）。真机上两个都叫 `media` 的成员在前四处已经分得出（批次四十六），而后两处还各写各的：屏幕阅读器把两枚勾选框念成同一句话，Context Packet 那张表里两行都叫 `media`。现在六处全走后端那张共用表（`displayName`，含 `#2`）。同一条口径的另一面：**系统行**（「X 加入了这个组」「X 被暂停」「X 是组长」）也是名字，也走同一张表。

- **原标题不丢**：成员栏与 Context Packet 那一格把会话标题挂在 `title=` 上（悬停看得到），名字那一栏只放显示名。
- **两个名字，两个入口**（AD-173）：**会话自己的名字**在会话页**点一下页头那行标题**就地改（Enter 存 / Esc 收，页头不因此多一枚按钮——★H）；**他在这个组里叫什么**在成员「…」菜单里（「在本组叫什么」，写 `roleLabel`，留空 = 恢复成会话标题）。后者只影响这个组，前者全站生效。回执点名的是**后端重算之后**的名字：用户敲「写手」而组里已经有一位写手时，他接下来真的会被告知的名字是「写手#2」。
- **「添加成员 → 选择已有会话」每行是「标题 · 引擎 · 项目」**（真机「藏过头了」第 1 条）：长列表里几条同名的旧会话此前长得一模一样。缺的那一段**整个不出现**（AD-71：不写「未知引擎」），所以只有标题时这一行与从前一个字不差。**不加搜索**——`BarMenu` 项数多了自己带过滤框。

### K. 「应用到引擎」弹窗（物化差异，2026-09-05）

项目页引擎卡上一枚中性按钮「应用到引擎」，点开是一个 720px 的弹窗。**打开只预演**（`confirm=0`），弹窗顶上第一句就说清楚"此刻磁盘上一个字节都没动"。

**三段，顺序固定：**

1. **将写入** —— `applied[]` 里 `action` 为 `set` / `unset` 的行。一行四格：能力名（`capGroup.*` 查表，查不到用 `capability_id`）· 键路径 · 一枚中性 Pill（写入 / 清空）· `before → after`。
2. **无变化** —— `unchanged` 的那些行**默认折叠成一个计数**（「无变化 N 项」），展开才逐行列出。它是"这次什么都没动"的证据，不是要读的内容。

**三段的标题始终可见（2026-09-05，batch27 热修，真机 A1）。** 三段各带计数（将写入 N / 无变化 N / 不会写入 N），**某一段是 0 也留着标题**——"这次没有要写的""这次没有被挡下的"本身就是这次预演的结论，把空段整个折没了，用户只会以为弹窗少了一块。「无变化」仍旧**默认折叠**：常显的是它的标题与计数，不是它的行。
3. **不会写入** —— `unsupported[]` 按 `reason` 分组，顺序是 `credential_bearing` → `factory_protected` → `not_mapped` → `not_blockable`。`credential_bearing` 那组下面永远有一句固定说明「凭据永远不由仪表盘写入。」；`factory_protected` 那组下面是一枚「接管这些键，本次一并写入」复选框——勾上即以 `adopt=1` **重新预演**，那些键于是从这一段挪进第一段，用户看得见自己刚才勾出了什么。

**值的规则（三条）：** ① 一律等宽（`--theme-font-mono`）；② 对象与数组折成**一行 JSON**，不做多行美化——差异行要对齐着扫，不是要读结构；③ 超过 72 个字符截断成 `…`，旁边一枚「展开完整值」，展开后仍是等宽、允许换行。空值显示「（空）」而不是空白，`null` 与空串在这里是同一件事：那个键当下没有值。

**语义色只在两处：** 底部 409 `binding_busy` 的红条（「有 N 条会话在运行，先停止再写」+ 「重试」），以及通用写入失败那一行。**差异行本身一律中性**——绿/红标记"增/删"在配置差异里会误导：这里没有"好的改动"与"坏的改动"，只有"要写的"与"不写的"。

**底部：** 后端的 `warnings[]` 原样逐条列出（含 dry-run 那一句），然后「关闭」与主按钮「备份后写入」。`applied` 里一条 `set`/`unset` 都没有时主按钮**禁用**，并在「将写入」那段写「没有需要写的改动」。写成功后弹窗整个换成成功态：一句「已写入」+ 备份路径 + 等宽的回滚命令（`cp <backupPath> config.yaml`，文案与 `docs/ops/projection.md` §3 同源），并触发一次 drift 重取。

**配置漂移**是同一个弹窗的**只读模式**：引擎卡上多一行「配置漂移」——`driftedCount > 0` 时「N 处被引擎侧改过」+ 「查看」，为 0 时「与项目一致 · 检查于 <时间>」。只读弹窗按 `expected` / `actual` 两栏列出 `drifted` 与 `missing` 的行；`unmanaged` 不计数也不列（它不是"对不上"）。**读不到 drift（端点不在 / `projection_unsupported` / 这次没读着）时，按钮与漂移行两处都不渲染**（AD-71 / AD-126：能力入口只看入口，不摆一个按下去必然报错的按钮）。只读弹窗底部除「关闭」外还有一枚主按钮**「用项目配置覆盖引擎侧」**（2026-09-05，batch27 热修，真机 A4）：它不另开界面，就是**切到同一枚弹窗的 materialize 流程**（照旧先 dry-run，写入仍要用户再按一次「备份后写入」，写完刷新 drift）；没有对不上的键时这枚不给。检查时间那一格是**本地可读的时间**，不是后端那串 ISO——后端的 ISO 带微秒六位，`Date` 只认到毫秒，先削掉再解析，解析不了才原样回显。

### L. 信息密度收敛（2026-09-08，批次四十，据 `audit-2026-09-08/` 的密度审计定案）

**原则（一句话）：每一个常显的元素都必须回答「我在做什么 / 谁在做 / 什么等着我」；其余的一律放到一次点击之外。**

审计的事实（`docs/frontend/audit-2026-09-08/inventory.md`）：首页 17 枚按钮里没有一枚通向"我手上的活"；项目页 51 枚按钮、19 行常显信息，其中 13 行是 `value={…}` 的原始 JSON；会话页与草稿页各有 6 行常显信息，其中一半是标签而不是取值。这不是审美问题——它让**唯一要紧的那一行**（哪条会话在跑、哪条等着你）和一屏取证资料混在一起。以下七条按屏施工，**其余一律保持现状**（AD-78：字体 / 图标 / 圆角 / 间距不动；★H 的中性配色不动，强调色仍旧只给运行点与审批边框）。

**L-1 概览页（`/`）= 工作台，不是封面。** 口号（`A SELF-GOVERNING FLEET OF AGENTS`）、`EST. 2026`、`KAUS CONTROL PLANE`、两条竖排标语、「VIEW AGENT」卡**全部删除**；KAUS 字标留一枚小的。换成三段 + 一枚主按钮「新会话」：

1. **「继续」** —— 跨项目**最近 6 条**会话，运行中 / 待处理的排在前面；一行 = 状态点 · 标题 · 项目 · 引擎 · 运行态 · 相对时间。
2. **「需要处理」** —— 停着等人的（`paused`）与上一次没发出去的（`error`）；**一条都没有时整段不渲染**（不是空态文案）。
3. **「项目」** —— 一行一个项目 + 会话数（会话多的在前；还没有会话的项目也列出来，数是 0）。

三段**一条端点都不多加**：全部从已有的会话索引（`GET /api/conversations` + `GET /api/projects`）算，纯函数在 `lib/conversationIndex.ts` 里受单测。两条诚实边界：① 索引行**不带模型 id**，所以行上只写引擎名，不编一个模型出来（AD-71）；② 后端没有"跨会话待审批清单"这样一个端点，「需要处理」只按索引行那个封闭集合（idle | running | paused | ended | error）分档，别的档一条都不进来。会话功能 flag 关闭时仍旧是旧的 `HomeHero`，一个像素不动。

> **2026-09-13 用户裁决：概览页取消。**「没看懂——它展示的东西侧栏已经有了」。三段里「继续」「项目」是侧栏的复印件，用户看不出它回答了什么；剩下的「需要处理」不足以撑起一整页。于是 `/` 改为**新会话草稿页**（就是 `/new` 那一页，两处同一个组件），铭牌与「需要处理」随之搬过去：铭牌在最上面（**去掉那枚「新会话」按钮**——这一页本身就是新会话），「需要处理」紧随其后且**只在非空时出现**。左导航的「概览」整项拿掉（也不进「更多」）。`OverviewPage.tsx` 与 `overview.recent.*` / `overview.projects.*` / `overview.state.*` 三组词典键一并删除；`plateCounts` / `buildAttentionItems` 留在 `lib/conversationIndex.ts`，`recentConversations` 无人再用，已删。flag 关闭那一支（`HomeHero`）仍旧一个像素不动。

**L-2 全局左导航：三个常显 + 一枚「更多」。** 常显只留**每天都用**的三条路：新会话 / 概览 / 项目。仪表盘 / 任务板 / 资料库 / 仓库 / 设置这五个旧面板收进「更多」，**默认折着**，开合状态记 localStorage（读写各自 try/catch，存不下就回默认）。会话列表那一段照旧。flag 关闭时的那一列一个像素不动。

**L-3 项目页引擎卡：默认两行摘要。**

- **第二行**：模型 · 推理强度 · 登录态。两枚控件本身一个字不改（还是那套下拉 + 保存 / 取消 + 来源小字），只是**去掉标签**，值自己说话。**登录态只在没登录时占位**——`signed_in` 一个字都不写（"一切正常"不需要占一行），`unknown` 照旧整行不渲染（AD-71）。

  1. `driftedCount > 0` 的配置漂移（「N 处被引擎侧改过」+「查看」）；
  2. `probeState === "unavailable"` 时后端给的那句探测原因（不再只挂在 chip 的 `title` 上）；
  3. `signed_out` 与它后面那句下一步 hint（以及「去登录」按钮，仍按 ★J-3 的条件出现）。

**L-4 能力表：人话摘要 + 前 8 行。** 内容列不再是 `value={"pre_tool":"audit.sh"}`（`value=` 是导入侧的包装，花括号是序列化，两样都不是给人看的）。改成**一行摘要**，规则只看形状、不解释语义：① 标量原样（`mock-small`）；② 数组按逗号列（`shell, web, python`）；③ 对象——值全是空壳时只列键名（`filesystem, git`），否则列成 `键: 值`（`pre_tool: audit.sh`），多个用 `·` 分开，超过 4 项折成 `…`。**原始值仍然拿得到**：每行一枚「展开原始值」，展开后是等宽的一行 JSON（取证不因此变难）。整张表**默认只摊开前 8 行**，其余折在「显示全部 N 项」后面。

**L-5 会话页。** 页头保持：标题 · 运行态 · 「到终端打开」（右下角那枚「协作组 · N」照旧）。输入区工具栏的 chip（工作目录 / 引擎 / 模型 / 推理强度）**只显示取值**，标签退到 `aria-label` 与悬停的 `title` 上；工作目录截成**末两级**，完整路径在 `title` 里（★I 的老规矩，这里写成硬规则）。折叠着的推理行 / 工具行上，**已经跑完时不写行尾的状态词**（`完成` / `thinking`）——没有出错标记、没有耗时，本来就说明它跑完了；**运行中、失败、有耗时的照旧显示**，展开后状态词也照旧回来。

**L-6 侧栏会话行 = 一行。** 标题 · 组小标（只在它属于一个还开着的组时）· 相对时间。**引擎字母标去掉**——一行里同时有标题、组名、终端图标、引擎字母与时间时，最先被挤掉的恰恰是标题；引擎改挂在整行的 `title` 上（悬停可见）。

**L-7 草稿页（`/new`）** 除 L-5 那条 chip 规则外**不动**。

**这一条裁决没说到的地方，一律选更安静的那一个**——这是本节的兜底规则，不是一句客套话：新加的常显元素要能被上面那句原则回答，否则它属于"一次点击之外"。

## 0. 一页速览（给不写代码的人）

Kaus 是一个跑在你自己电脑上的"多引擎 AI 工作台"：左边一棵项目树，右边是对话。它要同时接好几种 AI 引擎（Hermes、Codex、Claude Code……），而且以后还会接更多。

这份规范要解决四件事，其中三件是"以后不会翻车"的保险：

1. **颜色不能按引擎分。** 如果给 Hermes 配绿色、Codex 配蓝色，接到第七个引擎时就没颜色可用了，而且色盲用户根本分不出来。所以**引擎靠名字和图标区分，颜色只表达状态**（正常 / 警告 / 出错 / 运行中）。
2. **深色浅色都得能看。** 现在的界面有一批文字在浅色模式下对比度不够（第 2.5 节列了实测数字，最差的只有 1.08，标准要求 4.5）。规范给出两套经过脚本验算的取值。
3. **"缺的功能不渲染"是视觉原则。** 这是已经拍板的产品规则（AD-71）：某个引擎不支持某功能时，界面上直接不显示那个按钮/栏位，**不写"本引擎不支持"这类备注**。规范把它落到组件层：每个卡片、每个栏位都要能"整块缺席"而不留空壳。
4. **去掉品牌霸屏。** 开源发布后界面上不该有"HERMES"大字和金属质感。金色和金属效果已在 2026-09-02 移除（`AGENTS.md:6`），但残留的变量名、大标题和装饰性背景还在，第 11 节列了清单。

## 1. 定位与原则

Kaus 是**本地运行的多引擎 Agent 工作台**。界面语言以中文为主，英文只用于代码、ID、引擎名等专有名词。

七条原则，冲突时按顺序取舍：

1. **克制优先于表现力。** 不做视觉发明。同一个信息只用一种表达方式。
2. **信息密度高于留白美学。** 这是工作台不是官网；一屏要放得下一棵树、一列会话、一段对话（`docs/product/baseline.md:1024` §7.5）。
3. **深浅两套都是一等公民。** 任何颜色都必须在两套主题下各有取值并各自达标，不允许"深色好看浅色凑合"。
4. **无品牌色霸屏。** 强调色只用于**小面积**：选中条、焦点环、图标、细分隔线。不做大块填充、不做渐变文字、不做背景大图。
5. **缺的功能不渲染。** 引擎不支持的能力，对应控件整块不出现，不留占位、不加备注（AD-71，`docs/architecture/decisions/2026-09-02-batch1-rulings.md:180`）。唯一例外：静默隐藏会让人误判系统状态时（如"运行中但不可中断"），改为在头部如实写状态文字。
6. **引擎不分配颜色。** 见第 2.4 节。
7. **无障碍是门槛不是加分项。** 对比度、焦点环、键盘可达三项不达标视为 bug（第 9 节）。

### 2.2 语义色 token（新定义）

规则：**组件只准引用语义 token，不准引用 `--gold*`、不准调 `cream()` 写文字颜色、不准写字面色值。**

命名统一前缀 `--k-`（Kaus），避免和 Tailwind / shadcn 兼容层的 `--color-*` 撞名。

#### 背景层级（三层，越上层越亮/越浮）

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--k-bg` | 页面画布、侧栏底 | `#eae7dd` | `#16180f` |
| `--k-surface` | 卡片、面板、表格容器 | `#f1eee5` | `#1e211a` |
| `--k-elevated` | 浮窗、下拉、弹窗、悬浮卡 | `#f8f5ec` | `#25281f` |
| `--k-scrim` | 弹窗遮罩 | `rgba(35,32,25,.22)` | `rgba(4,5,3,.58)` |

三层就够。需要第四层说明层次设计错了，改用边框或间距区分。

#### 文字层级（三档）

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--k-ink` | 正文、主标题、输入内容 | `#1a1a15` | `#edeadd` |
| `--k-muted` | 次要说明、字段标签、元信息 | 墨色 62% | 墨色 70% |
| `--k-faint` | 时间戳、计数、禁用态文字 | 墨色 52% | 墨色 50% |

"墨色 N%" = `color-mix(in srgb, var(--k-ink-base) N%, transparent)`，其中 `--k-ink-base` 即上表的 ink 实色。
**`--k-faint` 只准用于 ≥14px 或非关键信息**；关键信息一律 `--k-muted` 起步。

#### 边框

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--k-border` | 装饰性发丝线：卡片外框、分隔线 | 墨色 15% | 墨色 16% |
| `--k-border-strong` | **有意义**的边界：输入框、可点击控件外框、选中框 | 墨色 48% | 墨色 40% |

区分的理由：装饰线只要"看得出有条线"，可以很淡；但输入框的边框是**控件的唯一可见轮廓**，无障碍标准要求它对背景达到 3:1，现在的发丝线只有 1.35:1（第 2.5 节）。

#### 强调色（一种，非金色）

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--k-accent` | 强调色**文字/图标**、焦点环 | `#4a6410` | `#b8dc4a` |
| `--k-accent-edge` | 纯装饰：选中条、进度条填充、细高亮线 | `#c4ee45` | `#cbee52` |
| `--k-accent-soft` | 强调色底（chip 背景、选中行底） | `rgba(196,238,69,.16)` | `rgba(203,238,82,.12)` |

色相沿用现有青柠（`--gold`/`--gold-deep` 的取值），只把浅色模式的文字档从 `#7f9a22` 压深到 `#4a6410`——现值对比度 2.59:1，远低于 4.5:1（第 2.5 节）。
**`--k-accent-edge` 明确标注为装饰**：它在浅色底上只有 1.08:1，永远不许承载文字或独自表达信息。

#### 状态色（五种）

| Token | 语义 | 浅色 | 深色 |
|---|---|---|---|
| `--k-ok` | 成功、就绪、已连接 | `#2f6b2f` | `#7fc47f` |
| `--k-warn` | 警告、降级、需要注意但没坏 | `#845408` | `#e0a458` |
| `--k-error` | 失败、断开、危险操作 | `#a8452a` | `#e08a6a` |
| `--k-info` | 中性提示、系统消息 | `#2f6090` | `#7fb0dd` |
| `--k-running` | 运行中、流式输出中 | `#6b6357` | `#a49b8c` |

`--k-running` 刻意做成**中性灰**而不是彩色：运行中是最高频状态，如果给它彩色，界面时刻在闪。运行中靠"脉冲动效 + 中性点"表达（第 8 节），不靠颜色抢眼。

每种状态色另配一个 `-soft` 底色（同色相 12–16% 透明），用于 chip 背景和卡片左边条底，取值见 `design-tokens.json`。

### 2.3 状态色怎么配文案与形状

**颜色永远不是唯一的信息载体**（色盲用户约占男性 8%）。任何用状态色表达的东西，必须同时具备下列至少一项：

- 一个图标（lucide-react 已在依赖里，`web/package.json`）；
- 一段文字（"已连接" / "已断开"）；
- 一个形状差异（实心点 / 空心圈 / 斜纹）。

状态点的形状约定：`ok` 实心圆、`warn` 实心三角、`error` 实心方、`info` 空心圆、`running` 实心圆 + 脉冲。

### 2.4 引擎不分配颜色（硬规则）

**不得给任何 Backend / 引擎分配专属颜色。** 多引擎靠三样东西区分：

1. **短标签**：`[H]` Hermes、`[C]` Codex、`[CC]` Claude Code（这个写法已在基线里，`docs/product/baseline.md:1029-1033`、`:2372-2376`）；
2. **图标**：每引擎一个单色线性图标，使用 `--k-muted` 或 `--k-ink`，不上色；
3. **全称文字**：会话头部第二行写全称（`docs/product/baseline.md:2404`）。

理由（给验收方）：颜色是**有限资源**。给前三个引擎配了颜色，第四个开始就只能用越来越难分辨的色相；等到第七、第八个，用户既分不出颜色，也已经养成"看颜色认引擎"的习惯，反而更容易认错。标签和图标是无限资源，加一个引擎加一个标签就行。

### 2.5 现状体检：哪些颜色现在不达标

用第 12 节的脚本对**现有取值**算了一遍（WCAG 2.1，正文门槛 4.5:1）：

| 主题 | 现有用法 | 值 | 底色 | 对比度 | 结论 |
|---|---|---|---|---|---|
| 浅色 | `--gold-deep` 作文字（`ui.tsx:125,171,187`，全仓 95 处） | `#7f9a22` | `#eae7dd` | **2.59** | 不达标 |
| 浅色 | `--gold-deep` 于 `--panel` 上 | `#7f9a22` | `#f1eee5` | **2.76** | 不达标 |
| 浅色 | `--gold` 作文字 | `#c4ee45` | `#eae7dd` | **1.08** | 严重不达标 |
| 浅色 | `--danger` 作文字（`ui.tsx:28,35,81`） | `#c2603a` | `#eae7dd` | **3.38** | 不达标 |
| 浅色 | `var(--warning,#d98a55)` 回退值 | `#d98a55` | `#eae7dd` | **2.20** | 不达标 |
| 浅色 | `--color-success`（`index.css:269`） | `#4ade80` | `#eae7dd` | **1.41** | 严重不达标 |
| 浅色 | `cream(55)` 作文字（`ui.tsx:122,252`） | 合成 `#78766f` | `#eae7dd` | **3.67** | 不达标 |
| 浅色 | `cream(45)` 作文字（`ui.tsx:27,46,190,200`） | 合成 `#8c8b83` | `#eae7dd` | **2.77** | 不达标 |

新 token 的完整验算见第 12 节，**66 项受检全部达标**。

## 3. 字体

### 3.1 现状

- 无衬线：`"Inter", "PingFang SC", ui-sans-serif, system-ui, sans-serif`（`theme-overrides.css:10-11`）
- 展示体：`"Anton", Impact, "PingFang SC", sans-serif`（`theme-overrides.css:12`）
- 等宽：`"Space Mono", ui-monospace, SFMono-Regular, Menlo, monospace`（`theme-overrides.css:13-14`）
- 终端另有内嵌 JetBrains Mono（`index.css:11-31`，woff2 在 `web/public/fonts-terminal/`）
- 基准字号 `15px`、行高 `1.55`（`index.css:65-66`）
- Inter / Anton / Space Mono 由 **Google Fonts CDN** 加载（`web/index.html:10`）

### 3.2 规范

**字体栈（三套，不增加第四套）**

| 角色 | 栈 | 用途 |
|---|---|---|
| `--k-font-sans` | `"Inter", "PingFang SC", "Microsoft YaHei", ui-sans-serif, system-ui, sans-serif` | 界面全部文字 |
| `--k-font-mono` | `"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` | 见 3.5 |
| `--k-font-display` | **取消**，等同 `--k-font-sans` | 见 3.4 |

中文回退顺序固定为 `PingFang SC`（macOS）→ `Microsoft YaHei`（Windows）→ 系统默认。西文字体必须排在中文之前，否则中文字体会把西文数字也接管，字宽会跳。

**关于 Google Fonts**：Kaus 是本地优先的工具，界面不该在断网时变样、也不该把用户访问时间发给第三方 CDN。规范要求 **Phase 2 把 Inter 与 JetBrains Mono 一并自托管**（JetBrains Mono 已经是自托管的，照抄同样做法），移除 `web/index.html:10` 的外链。这既是隐私也是离线可用性。

### 3.3 字号阶梯（六档，不许加档）

| Token | 尺寸 / 行高 | 用途 |
|---|---|---|
| `--k-text-xs` | 11px / 1.4 | 状态角标、chip、表头、时间戳 |
| `--k-text-sm` | 12px / 1.45 | 元信息、字段标签、树节点次要行 |
| `--k-text-base` | 13px / 1.55 | **界面默认**：按钮、输入、列表、表格 |
| `--k-text-body` | 15px / 1.65 | 对话正文（唯一需要长时间连续阅读的地方） |
| `--k-text-lg` | 18px / 1.4 | 面板标题、卡片区块标题 |
| `--k-text-xl` | 24px / 1.3 | 页面标题（每页最多一个） |

只有两档字重：`400`（正常）与 `600`（强调）。**不用 700 及以上**——现有代码里有多处 700/800/900（如 `index.css:150,173,200`、`theme-overrides.css:495,572,642,744,1757`），在中文下会触发合成加粗，糊。

`--k-text-body` 比界面默认大 2px 是刻意的：信息密度高的地方要密，但对话正文是要读的，密了伤眼。

### 3.4 展示体（Anton）取消

Anton 是海报级重量的展示体，只用在首页大标题（`HomeHero.tsx:52-56`、`theme-overrides.css:12`）。它不支持中文（会回落到 `PingFang SC` 的常规字重，中英混排时字重不一致），而且和"克制、无品牌霸屏"直接冲突。**Phase 2 移除**，首页标题改用 `--k-text-xl` + 字重 600。

### 3.5 等宽字体的用途（限定四类）

等宽字体只准用于：**① 终端与终端输出；② 代码块与内联代码；③ ID / 哈希 / 路径 / token；④ 需要按列对齐的数字（用量、耗时、行数）。**

其他任何地方（包括按钮、标签、导航）一律无衬线。当前 `input` 的字体被硬编码成等宽（`web/src/components/ui.tsx:255`：`font: "12px var(--theme-font-mono, monospace)"`），除非该输入框专收路径/ID，否则 Phase 2 改回无衬线——中文在等宽栈里没有等宽字形，会退到默认中文字体，和西文的 Space Mono 高度不匹配。

## 4. 间距与圆角

### 4.1 间距阶梯（4 基准）

Tailwind v4 的 `--spacing` 已经设成 `0.25rem × 倍率`（`web/src/index.css:104-106`），即 1 单位 = 4px。沿用，不另造体系。

| 阶 | 值 | 典型用途 |
|---|---|---|
| 1 | 4px | 图标与文字之间、chip 内左右 |
| 2 | 8px | 同组元素之间、按钮内左右（小） |
| 3 | 12px | 卡片内元素之间、表格行内边距 |
| 4 | 16px | 卡片内边距、面板内边距 |
| 6 | 24px | 区块之间、页面左右边距（窄屏） |
| 8 | 32px | 页面左右边距（宽屏）、大区块之间 |

**只用 1/2/3/4/6/8 这六阶**，不用 5、7 或任何奇数派生值。理由：阶梯少，肉眼才看得出"这两块是一组、那两块不是一组"；阶梯多了等于没有阶梯。

### 4.2 圆角（三档）

| Token | 值 | 用途 |
|---|---|---|
| `--k-radius-sm` | 4px | chip、状态角标、小按钮、输入框 |
| `--k-radius-md` | 8px | 卡片、面板、下拉、toast |
| `--k-radius-lg` | 12px | 弹窗、浮窗（Group）、抽屉 |

**外加两个特例**：状态点等正圆用 `50%`；分段控件的胶囊形用 `999px`——两者都不是"圆角"，是形状。

现有代码里同时存在 `0`、`1px`、`2px`、`3px`、`6px`、`7px`、`8px`、`9px`、`10px`、`12px`、`999px` 至少十一种圆角（`theme-overrides.css` 全文统计），Phase 2 按上表就近归并。

### 4.3 容器内边距规范

| 容器 | 内边距 | 说明 |
|---|---|---|
| 卡片（有标题） | 头部 `12px 16px`，正文 `16px` | 头部与正文之间一条 `--k-border` |
| 卡片（无标题） | `16px` | |
| 面板 / 全屏模块 | 左右 `24px`，上下 `20px` | 现值为 `28px`（`ui.tsx:121,148` 的 `px-7`），归并到 24 |
| 弹窗 | `20px` | |

| 表格行 | `8px 12px` | 密度优先 |
| 树节点 | `6px 8px`，每层缩进 `16px` | |

## 5. 组件基线

只定义"这是什么、什么时候用、什么时候不用"。所有组件都建立在 `web/src/components/ui.tsx` 现有原语上，**不引入新 UI 框架**（现有栈：Tailwind v4 + lucide-react 图标 + xterm 终端，见 `web/package.json`）。

### 5.1 按钮（四种，不许有第五种）

| 变体 | 视觉 | 何时用 | 何时不用 |
|---|---|---|---|
| 主（primary） | `--k-accent-soft` 底 + `--k-accent` 字 + `--k-accent` 描边 | 一屏/一个弹窗里**唯一**的主要动作 | 一个区域出现两个主按钮时——说明没想清楚主动作是哪个 |
| 次（secondary） | 透明底 + `--k-border-strong` 描边 + `--k-ink` 字 | 并列的常规动作 | 只有一个动作时（那就用主） |
| 危险（danger） | 透明底 + `--k-error` 描边与字 | 删除、强制接管、断开等不可逆动作 | 仅仅是"取消"——取消是次要按钮不是危险按钮 |
| 幽灵（ghost） | 无底无边，仅 `--k-muted` 字/图标，悬停加底 | 工具栏图标、行内次要动作、关闭按钮 | 承载页面主动作 |

现状对照：`ui.tsx:61-95` 只有 `primary/ghost/danger` 三种，`ghost` 实际带描边（`HAIR`），承担了"次"的职责。Phase 2 拆成四种，把带描边的现 `ghost` 改名为 `secondary`，新增真正无边的 `ghost`。

尺寸两档：默认高 28px（`--k-text-base`），紧凑 24px（`--k-text-sm`，仅用于表格行内和工具栏）。

**危险动作必须二次确认**（现有 `confirmAsync`，`ui.tsx:302-325`），确认弹窗里的确认键用危险变体。

### 5.2 输入

单行输入、多行输入、搜索框共用一套外观：`--k-surface` 底、`--k-border-strong` 描边、`--k-radius-sm`、内边距 `6px 10px`、字体 `--k-font-sans` `--k-text-base`。

- 聚焦：描边换成 `--k-accent` 并加 2px 焦点环（第 9 节）。
- 出错：描边换成 `--k-error`，下方一行 `--k-text-sm` 的 `--k-error` 文字说明。
- 禁用：底色不变、文字降到 `--k-faint`、描边降到 `--k-border`、光标 `not-allowed`。
- **占位符不代替标签。** 标签在上方，`--k-text-sm` + `--k-muted`；占位符只给格式示例。

何时不用：只有两三个固定选项时用分段控件，不用下拉；只有开关语义时用开关，不用下拉。

### 5.3 下拉 / 选择

`--k-elevated` 底、`--k-radius-md`、`--k-shadow-md`、最大高度 `320px` 后滚动。选项超过 8 条必须带搜索框。当前选项用 `--k-accent-soft` 底 + 左侧 2px `--k-accent-edge` 条。

何时不用：选项会随引擎能力变化到"可能一条都没有"时，整个下拉不渲染（原则 5），不要渲染一个空下拉。

### 5.4 标签 chip

小圆角矩形，`--k-text-xs`，内边距 `2px 6px`，底色为对应语义的 `-soft`，文字为对应语义实色。

用途限定三类：**① 引擎标签**（`[H]`/`[C]`，中性色）；**② 状态标签**（用状态色）；**③ 计数/元信息**（中性色）。
何时不用：不要用 chip 做导航、不要用 chip 做可点击的按钮——它看起来不像能点。

**不做大写字母加宽字距。** 现有 `Pill` 是 `uppercase tracking-[0.14em]`（`ui.tsx:53`），中文里"字距加宽 + 全大写"没有意义，且中英混排时高度不齐。

### 5.5 状态点

直径 8px 的圆（或第 2.3 节约定的形状），后面跟一段 `--k-text-sm` 状态文字。**点不能单独出现**——单独一个彩色圆点是无法读屏的。

`running` 状态的点带脉冲动效（第 8 节），其余静态。

### 5.6 卡片壳

一个矩形容器：`--k-surface` 底、1px `--k-border` 边、`--k-radius-md`。可选头部（标题 + 右侧动作），头部与正文之间一条 `--k-border`。

**卡片壳不认识内容。** 头部标题、图标、右侧动作全部由调用方传入；卡片壳不许根据引擎名做条件分支（这是 D-13 的口径，`docs/product/baseline.md:2344`）。

### 5.7 面板

占满一块工作区的容器（项目详情页的各个分区、全屏模块）。与卡片的区别：面板**没有外框**，靠标题和间距分区；卡片有外框，用于并列展示的同类项。

一屏里不要嵌套超过两层容器（面板里放卡片可以，卡片里再放卡片不行）。

### 5.8 浮窗（Group 用）

右下角固定入口，可打开/最小化/关闭，跨页面保持（`docs/product/baseline.md:2425-2437`）。
`--k-elevated` 底、`--k-radius-lg`、`--k-shadow-lg`、默认宽 `360px`、最大高 `70vh`。

何时不用：浮窗只给 Group（跨会话的成员编排）。任何"某个页面的辅助信息"都不该做成浮窗——那是抽屉或面板。

### 5.9 树节点

一行：`[展开箭头] [引擎标签] [名称] [右侧状态/计数]`。每层缩进 16px，行高 28px。

- 选中：`--k-accent-soft` 底 + 左侧 2px `--k-accent-edge` 竖条。
- 悬停：`--k-ink` 的 4% 底。
- 拖拽目标：2px `--k-accent` 虚线框。

树**只展示 Project**，会话在项目节点展开区里（`docs/product/baseline.md:2353`）。`visibility = group_only` 的会话不出现在树里（同上 `:2368`）。

### 5.10 表格行

行高 32px，内边距 `8px 12px`，行间只有一条 `--k-border` 分隔线，**不做斑马纹**（斑马纹在高密度表格里会和状态底色打架）。悬停整行加 `--k-ink` 4% 底。

何时不用：字段少于三列时用字段行（`FieldRow`，`ui.tsx:197-204`），不用表格。

## 6. 对话卡片的视觉语法

这一节给阶段 3A/3B 的卡片对话页用。**七种卡片共用一套骨架**，差异只在正文区。

### 6.1 统一骨架

```text
┌────────────────────────────────────────────────┐
│ [H] Hermes   工具调用            14:32   [∨]   │  ← 头部：24px 高
├────────────────────────────────────────────────┤
│ 正文（每种卡片不同）                            │
└────────────────────────────────────────────────┘
```

- **头部固定四段**：引擎标签（chip，中性色）· 卡片类型（`--k-text-sm` `--k-muted`）· 时间（`--k-text-xs` `--k-faint`，右对齐）· 折叠箭头（可选）。
- 卡片壳：`--k-surface` 底、`--k-radius-md`、1px `--k-border`。
- **状态只通过左边一条 3px 的竖条表达**，颜色取状态色；正常态无竖条。这是全局唯一的"状态上色"位置，正文文字永远是 `--k-ink`/`--k-muted`。
- 连续同一引擎的多张卡片，**头部只在第一张显示**引擎标签，其余省略——密度优先。

### 6.2 七种卡片

| 卡片 | 正文结构 | 状态竖条 | 默认折叠 |
|---|---|---|---|
| **文字卡** | 纯 Markdown 正文，`--k-text-body` | 无 | 否 |
| **工具卡** | 两栏：左"调用"（工具名 + 参数，等宽），右"输出"（等宽，超长折叠） | 无 / `error` | 否 |
| **审批卡** | 一句请求说明 + 主/次两个按钮 + 可选"记住此选择" | `warn` | 否 |
| **提问卡** | 问题文字 + 输入或选项 + 提交按钮 | `info` | 否 |
| **推理卡** | 折叠标题"思考过程 · N 秒"，展开是 `--k-muted` 正文 | 无 | **是** |
| **报错卡** | 一行错误摘要（`--k-ink`）+ 可展开的原始错误（等宽 `--k-faint`）+ 可选重试按钮 | `error` | 详情折叠 |
| **用量条** | 单行：tokens / 耗时 / 模型，`--k-text-xs` `--k-faint`，等宽数字 | 无 | 否 |

### 6.3 工具卡的"输出栏可缺席"

这是 AD-71 落到视觉的关键点（`docs/architecture/decisions/2026-09-02-batch1-rulings.md:180,191`）。当引擎的能力矩阵里 `card.tools.output` 为不支持时：

- **右侧输出栏整块不渲染**，左侧调用栏撑满卡片宽度；
- **不显示**"该引擎不提供工具输出"之类的备注；
- 卡片不留空栏、不留占位灰块、不留分栏竖线。

同理：ACP 引擎没有会话发现能力时，界面上就没有"从引擎导入会话"入口。想知道"为什么没有这个按钮"的人去项目详情页的"已接引擎"面板看能力清单（AD-71 指定的两个 note 落点之一）。

### 6.4 流式中的表示

正在流式输出的卡片：

- 头部时间位置换成 `--k-running` 状态点（带脉冲）+ "生成中"；
- 正文末尾一个 1ch 宽的块状光标，用 `--k-running`，**不闪烁**（闪烁光标在长回答里很吵，用静态块即可）；
- **不用骨架屏**。文字是逐字来的，骨架屏会导致内容跳动。
- 流式结束后光标消失、状态点换成时间，**不做出场动画**。

### 6.5 卡片之间

垂直间距 12px。同一次请求内的卡片（文字→工具→文字）间距压到 8px，不同请求之间 24px。不画分组框。

## 7. 状态与空态

每个页面/面板必须显式实现下面六种态。**六种以外不许有第七种**，也不许某种态"忘了写"直接渲染空白。

| 态 | 长什么样 | 文案语气 |
|---|---|---|
| **空** | 居中一行 `--k-muted` 说明 + 一个主按钮（若有可做的动作） | "还没有会话。新建一个开始。" |
| **加载** | 内容区域内一个小旋转指示器 + "加载中"；**超过 400ms 才显示**（更短的加载显示指示器反而闪） | "加载中" |
| **正常** | 内容本身 | — |
| **出错** | 一行 `--k-error` 摘要 + "重试"次要按钮 + 可展开的原始错误 | "加载失败：连接被拒绝。" |
| **运行中** | 头部一个 `--k-running` 脉冲点 + 状态文字；**输入框保持可用**（`docs/product/baseline.md:2422` 明确要求不得渲染成只读） | "正在 Ghostty 中运行" |
| **引擎未就绪** | 面板位置一行 `--k-warn` 说明 + "检测状态"按钮 | "引擎未就绪：未找到可执行文件。" |

### 7.1 文案语气（硬规则）

- **中文，简短，一句话说清"发生了什么"，必要时第二句说"可以做什么"。**
- **不用感叹号。** 一个都不用。
- **不用"哎呀""糟糕""出错啦"这类拟人化。** 工作台不卖萌。
- **不把技术错误原样甩给用户当摘要。** 摘要写人话（"连接被拒绝"），原始错误放在可展开区里给会看的人。
- **不写"请稍候""正在努力加载"。** 写"加载中"。
- 按钮文案用动词："重试"、"新建会话"、"强制接管"，不用"确定"。

## 8. 动效

**只允许三种动效，没有第四种。**

| 动效 | 时长 | 缓动 | 用在哪 |
|---|---|---|---|
| 淡入（含轻微位移 ≤4px） | 160ms | `ease-out` | 弹窗、下拉、toast、浮层出现 |
| 高度展开/收起 | 200ms | `ease-out` | 推理卡、报错详情、树节点展开 |
| 状态点脉冲 | 1600ms 循环 | `ease-in-out` | 仅 `running` 状态点 |

时长三档：`--k-motion-fast: 120ms`（悬停/颜色过渡）、`--k-motion-base: 160ms`（进出场）、`--k-motion-slow: 200ms`（尺寸变化）。**没有超过 200ms 的动效**（脉冲是循环，不算过渡）。

**明确禁止**：滑入滑出、弹跳、缩放大于 ±2%、旋转（加载指示器除外）、逐字打字机效果、视差、任何超过 200ms 的过渡。

### 8.1 `prefers-reduced-motion` 必须尊重

**现状：全仓 `web/src/` 没有任何一处 `prefers-reduced-motion`（已全文检索确认）。这是必须补的无障碍缺陷。**

规范：全局加一段，Phase 2 落地：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

脉冲点在该模式下变成静态实心点（信息不丢失，只是不动）。加载指示器改为静态文字"加载中"。

给验收方的解释：部分用户（前庭功能障碍、偏头痛）会在系统设置里打开"减少动态效果"。操作系统会把这个偏好告诉网页，网页有责任照做。这不是可选项，是无障碍基线。

## 9. 无障碍

三条硬门槛，不达标视为 bug：

### 9.1 对比度（WCAG 2.1 AA）

- 正文与图标类文字：**≥ 4.5:1**
- ≥18px 或加粗 ≥14px 的大字、非关键文字（`--k-faint`）：**≥ 3:1**
- 有意义的非文字元素（输入框边框、焦点环、状态点、图表色块）：**≥ 3:1**
- 纯装饰（`--k-border` 发丝线、`--k-accent-edge` 高亮条）：不设门槛，但**不许独自承载信息**

第 2.2 节的全部 token 已按此验算通过（第 12 节，66 项受检 0 项未达标）。**改任何颜色前先跑一遍脚本。**

### 9.2 焦点环

- 任何可聚焦元素在键盘聚焦时必须有可见焦点环：2px `--k-accent` 实线 + 2px 与元素之间的间隙（`outline` + `outline-offset`）。
- **不许 `outline: none` 而不给替代。** 这是最常见的无障碍破坏方式。
- 鼠标点击不必显示焦点环（用 `:focus-visible`），键盘 Tab 必须显示。

### 9.3 键盘可达最低要求

- 所有按钮、链接、输入、下拉、树节点、卡片内动作都能用 Tab 到达，Enter/Space 激活。
- 弹窗与浮窗打开时焦点移入，Esc 关闭，关闭后焦点回到触发元素。**Esc 只由最顶层弹窗消费**（现有实现已经正确，`ui.tsx:209-228`，注释说明了为什么）。
- 树用方向键导航：上下移动、右展开、左收起。
- 焦点顺序 = 视觉顺序。不用 `tabindex` 正数。
- 只有图标的按钮必须有 `aria-label`（现有 `Overlay` 的刷新按钮已经做了，`ui.tsx:138`，照抄）。

## 12. 对比度验算（脚本与结果）

### 12.1 脚本

保存为任意位置的 `contrast.py`，`python3 contrast.py` 运行；全部达标退出码 0，有未达标项退出码 1、并在末尾列出。**改任何 token 取值后必须重跑。**

```python
#!/usr/bin/env python3
"""Kaus DESIGN.md 语义色 token 对比度自检（WCAG 2.1 相对亮度）。

判定门槛（AA）:
  正文/图标类文字 token                              >= 4.5
  次要文字 (faint)                                   >= 3.0
  有意义的非文字边界 (border-strong / focus)          >= 3.0
  纯装饰 (border / accent-edge)                      不设门槛，仅报告数值
"""
import json, sys

def hexrgb(h):
    h = h.lstrip('#')
    if len(h) == 3: h = ''.join(c*2 for c in h)
    return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def over(fg, alpha, bg):
    """把 fg 以 alpha 叠在 bg 上（sRGB 直接混合，等价于 CSS color-mix in srgb）。"""
    f, b = hexrgb(fg), hexrgb(bg)
    return tuple(round(f[i]*alpha + b[i]*(1-alpha)) for i in range(3))

def lum(rgb):
    def ch(c):
        c = c/255
        return c/12.92 if c <= 0.04045 else ((c+0.055)/1.055) ** 2.4
    r, g, b = (ch(c) for c in rgb)
    return 0.2126*r + 0.7152*g + 0.0722*b

def ratio(a, b):
    la, lb = lum(a), lum(b)
    hi, lo = max(la, lb), min(la, lb)
    return (hi+0.05)/(lo+0.05)

def tohex(rgb):
    return '#%02x%02x%02x' % rgb

    return hexrgb(v) if isinstance(v, str) else over(v[0], v[1], base)

        for tok, need in TARGET.items():

                         "target": need,

    return rows
```

### 12.3 未做的验算（诚实标注）

- **状态色的 `-soft` 底色上的文字对比度未核实。** `design-tokens.json` 给了 `-soft` 取值，但"状态色实色写在同色相 soft 底上"这一组合尚未验算，Phase 2 实现 chip 时补跑。
- **`--k-scrim` 遮罩之上的内容对比度未核实**（遮罩下面是任意页面内容，无法静态验算）。规范要求：弹窗自身用 `--k-elevated` 实色底，不依赖遮罩产生对比。
- **实际渲染的次像素抗锯齿影响未核实。** 脚本算的是纯色对纯色，细字体在实际渲染中的有效对比度会略低于计算值——这是所有对比度工具的共同局限，也是本文把门槛卡在标准值而不留余量的地方要留意的点。

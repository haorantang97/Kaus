# 界面审视与调整方案（2026-09-28）

**范围：** `web/` 当前主路径——草稿页 `/new`、会话页、侧栏、项目页、协作组浮窗、轮盘 `/agents`，浅色 / 深色 / 390px 窄屏。
**方法：** 本机后端 + Mock 引擎，Playwright（Chromium）逐屏走查并截图；样式层做了静态统计。截图含本机路径与会话内容，未入库。
**性质：** 记录与方案。本轮只修了**功能性**的界面缺陷（见 §1），视觉体系暂不动；§3 起是可提升点与调整方案，按 §7 的阶段实施。

与 `DESIGN.md` 的关系：本文不推翻 ★ 定稿裁决（字标、中性工作区、强调色只给运行点与审批边框）。多数建议是**把 DESIGN.md 已经写好、但没有落地**的部分落地（最典型的是 §2.2 的语义色 token），外加几处新的版式与动效提案，标注为「提案」，需要用户裁决。

## 3. 体系层：可提升点与方案

### 3.1 颜色：把 DESIGN §2.2 落地

DESIGN.md §2.2 早已定义了 `--k-ink / --k-muted / --k-faint / --k-border / --k-border-strong / --k-accent*` 与五种状态色，但代码里仍是 `cream(N)`。方案：

1. 在 `theme-overrides.css` 顶部按 DESIGN §2.2 的表定义 `--k-*`（浅色 / 深色两组）。`--k-muted` 浅色取墨色 **64%**（4.7:1），`--k-faint` 取 **56%** 并只允许用于 ≥13px 的非关键信息（时间戳、计数）。
2. `ui.tsx` 新增 `ink.muted / ink.faint / line.hair / line.strong` 常量（值就是 `var(--k-…)`），`cream()` 保留给背景叠色，**不再用于文字**。
3. 机械替换：`cream(38|40|42|45|50|55) → var(--k-faint|--k-muted)`（按用途二选一），`cream(14|16)` 边框 → `var(--k-border)`。可以写一个 codemod，按调用处的属性名（`color` vs `border`）分流。
4. lint 增加规则：`color:` 后面不许出现 `cream(`。

### 3.2 字体：三种字体各司其职

现状：Inter（正文）、Space Mono（大量界面标签）、Anton（字标 / 轮盘大字）。问题不在字体选择，而在 Space Mono 的**使用面过大**——侧栏会话标题、项目页会话列表、工具行名、输入框占位、所有大写小标签都是等宽。等宽 + 中文 = 两套字宽，基线与截断都不齐。

| 用途 | 字体 | 规则 |
|---|---|---|
| 字标、轮盘项目名 | Anton | 只在"门面"出现，工作区不出现 |
| 界面文字、标题、会话标题、按钮 | Inter + 系统中文 | 默认 |
| 代码、路径、模型 id、数值、键值 | Space Mono | `font-variant-numeric: tabular-nums` |

### 3.3 字号阶梯：20 档 → 6 档

| token | 值 | 用于 |
|---|---|---|
| `--k-text-2xs` | 11px / 1.4 | 计数、时间戳（唯一允许的最小字号） |
| `--k-text-xs` | 12px / 1.5 | 元信息、pill、表头 |
| `--k-text-sm` | 13px / 1.55 | 界面默认、侧栏、按钮 |
| `--k-text-md` | 15px / 1.65 | 会话正文 |
| `--k-text-lg` | 18px / 1.4 | 页标题 |
| `--k-text-display` | 32px / 1.1 | 草稿页标题 |

7.5–10.5px 的七档全部并入 11px。大写小标签（CONVERSATIONS / CONNECTED ENGINES / TYPE…）改为 **11px Inter 600、字距 0.04em、非全大写**；需要"章节感"的地方用字重与留白，不用 0.14–0.2em 的宽字距。

### 3.4 圆角：12 档 → 3 档

`--k-radius-control: 6px`（输入、按钮、pill 内部）· `--k-radius-card: 10px`（卡片、浮层、菜单）· `--k-radius-pill: 999px`（胶囊、发送键）。1 / 3 / 4 / 5 / 7 / 8 / 12 / 18 / 20 全部归并。

### 3.5 选中态与主按钮

现状：侧栏「New chat」与当前会话行都是整块深底反白，深色主题下是整块米白。一屏两个最强元素。

方案（提案）：
- **选中行**：`--k-surface` 浅一档的底 + 左侧 2px `--k-ink` 指示条，文字 600。
- **New chat**：描边按钮，或收进字标右侧一枚 `+` 图标按钮（带 tooltip 与 `⌘N`）。
- 深底反白只留给**当下唯一的主动作**（发送 / 停止）。

### 3.6 动效 token（新增）

统一三档：`--k-dur-1: 120ms`（hover / 按压）、`--k-dur-2: 200ms`（展开 / 折叠）、`--k-dur-3: 320ms`（浮层进出），缓动统一 `cubic-bezier(0.22, 1, 0.36, 1)`。`prefers-reduced-motion` 下全部降为 0。现在各组件各写各的时长。

## 4. 页面层：可提升点与方案

### 4.1 草稿页 `/new`

- **标题口吻**：「Let’s make something sick」是 README 的口号，放在每天打开的首页上显得随意。提案：标题改为时段问候 + 当前项目（「下午好 · default」），口号挪进关于页或空状态彩蛋。
- **Composer 工具栏**：`default ▾ · Hermes · default ▾ · Choose working folder · Mock Small ▾` 一行五个同权重文字 pill，第一眼分不清哪个是项目、哪个是引擎。方案：每枚 pill 前加 12px 图标（`Folder` / `Cpu` / `FolderOpen` / `Sparkles`），项目与引擎之间一条细分隔。
- **首次使用**：示例配置下默认挂载是**离线的 Hermes**，新用户第一句话必然失败；Mock 要手动去项目页接入。方案（产品）：没有可用引擎时 composer 上方一条中性提示「当前引擎未就绪 · 切换到 Mock / 去接入」，一键切换。
- **空白利用**：「需要处理」只在非空时出现是对的；可以再加「最近 3 条会话」的一行快捷入口（键盘 ↑ 可达），降低从草稿页回到工作的成本。

### 4.2 会话页

- **节奏**：用户消息与第一条助手内容之间约 100px 空白，而助手内部各行之间 50px，层级反了。方案：turn 之间 32px，turn 内部 8–12px；工具 / 推理 / 计划行共用一条左侧 1px 竖线（run rail），把"这一轮做了什么"串成一组。
- **动作栏**：每个助手文本块下常显「复制 + 时间」，流式中也挂着；在 Mock 下时间是 `00:00`（Mock 用固定 EPOCH，属测试夹具）。根因是两层样式互相打架：`theme-overrides.css`（`.kaus-msg:hover .kaus-msg-time` / `.kaus-msg-actions`）按 G-2 做成悬停才出现，而后加载的 `components/cards/conversationContent.css:8,12` 以 `opacity: 1` 把它们改成了常显。方案：删掉后者的常显覆盖，回到 hover / focus 出现（触控设备由 `@media (hover: none)` 常显），流式中不渲染。
- **流式光标**：`▌` 独占一行。改为内联在最后一个字符后。
- **运行态重复**：页头「● Running」+ 底部「● Mock is replying…」+ 停止键，三处说同一件事。提案：页头只在异常（离线、停止未确认）时出字；正常运行由 composer 上方那一行与停止键表达。
- **工具行**：`read_file · a.txt` 的工具名是等宽、参数是比例字，两种字混在一行。统一比例字，工具名 600。
- **页头图标**：`>_`（到终端打开）与 `…` 缺少可见 tooltip 延迟与 hover 底；补 `title` 之外的 tooltip 组件。

### 4.3 侧栏

- 会话标题改 Inter 13px；时间 `tabular-nums`，右对齐成一列。
- 项目组头「DEFAULT」改为原样大小写（项目名是用户起的名字，不该被强制大写）。
- 选中态见 §3.5。
- 运行中的点目前是强调色小点，建议加 1.6s 的呼吸（`opacity .5↔1`），与页头统一。

### 4.4 项目页

- **二级导航空列**：只有一个项目时左侧「PROJECTS」列占 300px，只放一行。方案：项目 < 8 个时改为页头的项目切换器（下拉），≥ 8 个才出二级导航。
- **卡中卡**：区块卡片里再套引擎卡片，三层边框。方案：引擎改为**列表行**（字母徽标 · 名称 · 状态点 · 模型 ▾ · 推理 ▾ · `⋯`），「应用到引擎 / 新会话 / 设为默认 / 解除」进 `⋯` 菜单，只留「新会话」常显。
- **错误长句**：探测失败原因以红字整段铺开（且为后端中文）。方案：状态 chip 旁一枚 `!` 图标，点开浮层显示原因与修复命令（可复制）。
- **表格溢出**：能力表的「ACTIONS」表头超出卡片右边界。
- **强调色**：页头「+ New conversation」是柠檬绿底，与 ★H「工作区中性」冲突；改中性描边或深底主按钮。

### 4.5 协作组浮窗

- 展开态 740×720 覆盖主内容，且开合状态存 sessionStorage，跨页面一直挡着正在读的会话；窄屏下直接盖住全部。
- 方案（提案）：展开态改为**右侧可停靠侧板**（推开主区，宽 420–560 可拖），收起仍是右下胶囊；或者给组一个独立路由 `/groups/:id`，浮窗只做快速切换。
- 键盘：浮层 `role="dialog"` 但 Esc 不关。要做 Esc 最小化，需先让浮层内菜单的 `useDismiss` 在处理 Esc 时 `preventDefault`，否则一次 Esc 会同时关菜单和浮层。
- 系统消息（「t1 加入了这个组」）与引擎提示是**后端生成的中文**，英文界面下照样是中文。方案见 §5。

### 4.6 轮盘 `/agents`

- Anton 超大项目名 + 左侧无标签浮动图标栏，与工作区的安静风格断层明显。按 ★D 保留手感与字标，但建议：浮动图标栏补 hover 标签，右侧信息面板与项目页共用同一套行组件。

### 4.7 响应式

- 390px：侧栏 280px 常驻，会话区约 150px，协作组浮窗覆盖全屏。
- 方案：`<900px` 侧栏改为左滑抽屉（顶栏出汉堡 + 当前会话标题）；composer 工具栏横向滚动；协作组展开态全屏 sheet。`<600px` 会话栏去掉左右 24px 留白改 16px。

## 5. 国际化

- 旧面板约 **570** 处硬编码中文：`KanbanOverlay`（158）、`ProfileDrawer`（137）、旧 `Conversation.tsx`（97）、`CoordinatorSettings`（41）、`cards/preview`（35）、`DriftAlert`、`ConstitutionEditor`、`ConfigOverlay`…

- 后端生成的人话（系统行、探测失败原因、失败提示）目前是中文句子。方案：后端给 `code + params`，前端按码查词典；拿不到码时才回显原文。

## 6. 让它"更高级、更有创意"的方向（提案，需裁决）

以下都守 ★H「工作区安静」：个性放在**动效与结构**里，不放在颜色里。

1. **Run rail（运行轨）**：每一轮在左侧有一条 1px 竖线，运行中从上往下"生长"（`scaleY` 动画），工具 / 推理 / 审批是轨上的节点。它把"agent 正在做什么"变成一个可以扫一眼的形状，也是 Kaus 可以拥有的视觉签名。
2. **命令面板 `⌘K`**：切会话、切项目、切引擎 / 模型、打开协作组、到终端打开。多引擎工作台的效率上限取决于键盘。
3. **引擎身份 monogram**：不给引擎分颜色（DESIGN §2.4），但可以给每个引擎一个 2 字母等宽徽标（CC / CX / OC / HM），全站统一出现在 composer、侧栏悬停卡、项目页行首。
4. **协作组"房间"可视化**：组头一排成员徽标，当前发言者徽标下有细下划线随发言接力移动；组长徽标带一个小角标。比文字「第 2/12 轮 · 轮到 B」更直观。
5. **会话导航条**：长会话右侧一条极细的 turn minimap（每轮一个刻度，审批 / 失败用形状标记），点击跳转。
6. **状态点语言**：DESIGN §2.3 已定形状约定（ok 圆 / warn 三角 / error 方 / running 圆 + 呼吸）——落地后，色盲用户也能一眼分清，且形成独特的"信号灯"细节。

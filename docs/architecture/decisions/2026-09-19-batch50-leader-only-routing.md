# 裁决记录：批次五十 下一轮队列只认组长的 `@`（2026-09-19，AD-171）

**背景**：批次四十八的第一份真机记录 `docs/quality/reports/2026-09-19-group/REPORT.md`（§3 ②③④、§4）。三场讨论（写手=`codex` 组长、评审=`hermes-acp`、打杂=`hermes`）全部跑通了「多引擎同组轮流 + 组长收口」，但 §4「模型不听话」清单里那一条是规格问题不是措辞问题：

> 打杂在 ② 末尾写了 `@写手`；评审写了 `@打杂`——点名格式有时用 `@名字`，符合约定。

**评审与打杂在每一轮结尾都 `@下一位`**（评审→`@打杂`、打杂→`@写手`）——它们把 AD-169 那句约定「想让谁接着说就写 `@名字`」读成了传话筒，而且三场一致。按第四次修订的「用户点、成员点、组长点三者同权」，这些接力 `@` 会把人塞进下一轮队列，于是**只要有一个成员这么写，终止 3「一轮结束、下一轮除组长外为空 → 停」就永远到不了**：三场（②③④）全是靠组长写「最终答复」才停的，`round` 都只有 1。

- **AD-171 路由只在组长手里：第一轮之后所有点名以组长为准。AD-169 的「三者同权」作废。**

  这一条**只动一件事**：下一轮队列从哪读。AD-169 的其余部分——组长是成员上的一个标记、它永远排本轮队尾、终止的那六条、「最终答复」只认组长、`@` 不提前到本轮下一位、`resolve_mentions` 的匹配规则——一个字没改。AD-168 的骨架（房间循环、串行、增量只含公开内容、`epoch`、「停」不打断正在跑的那一位）同样没动。

  ### 为什么是结构而不是措辞

  另一个选项（A）是只改约定的措辞：把「想让谁接着说就写 @名字」换成「别在结尾 @ 下一位」，`@` 仍旧三者同权。它不成立的理由，真机那三场自己给了：

  - **三台不同引擎、三场不同题目，两位成员一致地把约定读成了传话筒。** 这不是某一家模型的怪癖，是「结尾点一个人接着说」这件事在对话语料里的引力。改一句措辞是在赌下一台引擎读得更准，而房间**停不下来**是这局赌输的代价。
  - **终止 3 是这一版唯一不依赖模型写对四个字的终止条件。** 它的判据是「队列空」，而只要任何一位成员在任何一轮写了一个名字，这个判据就永远为假。一条**任何一个参与者都能单方面否掉**的终止条件，等于没有。
  - **六家里 AionUi / Semantic Kernel / MagenticOne 是纯形**：路由在一个人（或一段代码）手里，其余 agent 说的话是**内容**不是**指令**。我们此前把两者混在一起：同一段文本既是给别人读的内容，又是给房间读的路由表。

  所以这一条不是「教模型别那么写」，是**结构上堵死**：成员照旧可以写 `@`（写了也读得通，组长读全场，一定看得见），只是它不再改变谁说下一句。

  ### 落法

  - **`next_round_queue` 只读组长那一条**（`author_member_id == leader_id`）。本轮应当恰好有一条——组长是每一轮的最后一位。没有那条（组长略过 / 投递失败 / 组里没有组长）→ 没有人被点名 → 队列除组长外为空 → 终止 3 / 5。其余三步没变：`@所有人` 展开成全体 active、剔除非 active 与组长、组长追加到队尾。
  - **接入层照旧把整轮传进去**，由纯函数自己筛组长（任务书 §2.2 的二选一）。接入层少一处「谁是组长」的判断，而那件事纯函数本来就要知道（它得把组长追加到队尾）；两处各判一次，早晚有一天判得不一样。
  - **成员的点名落 `member_turn.metadata.mentions`**（新键，上 wire）。**它是证据不是路由**：时间线上必须看得出「评审点了打杂，但下一轮没有打杂」，否则「我明明 `@` 了他」只能靠读代码回答。组长那一条也记——它那一格正好就是下一轮队列的来源，对得上账。没点到人的那几条不带这个键；略过的那条不解析。
  - **三段房间文案重写**（`ROOM_CONVENTIONS` / `ROOM_CONVENTIONS_NO_LEADER` / `LEADER_NOTE`，逐字）。约定不再教成员点下一位——教了等于教它写一句不生效的话，而一句不生效的话比没有这句话更坏（成员以为自己安排了顺序）。`LEADER_NOTE` 多两句：「只有你的 `@` 算数」（告诉组长别人结尾那些 `@下一位` 不是路由）、「别为了礼貌点人」（防的是真机那三场里「点一个人接着说」的惯性，它是房间停不下来的另一半原因）。
  - **没有组长那一份约定只剩「略过」一条**。没有组长 = 没有人能点名 = 队列恒空 = 房间一轮即停，再教一句 `@名字` 是教一条永远不会被读到的话。

  ### 几处实现里自己拍的板

  - **约定那一段不再需要组长的显示名。** AD-169 特地把 PRD 里的「就写 `@组长`」换成真名字（`resolve_mentions` 认显示名，照抄那两个字谁也点不到）。这一版举手改成「在正文里写明」，于是这段文本与「组长叫什么」无关了，`room_delta` 里那次 `format` 一并去掉——少一个能填错的洞。
  - **组长那条真出现两条时都读。** 正常路径下本轮只会有一条（组长是队尾）；重放补记之类真弄出两条时，按时间线顺序都读一遍而不是只认第一条：多读一条**组长自己写的**名字不会把传话筒放回来。
  - **`mentions` 记「他点了谁」而不是「下一轮有谁」。** 后者是线程状态上的 `speakerQueue`，已经有了；这一格要答的是那件对不上的事——有名字、下一轮却没有他。
  - **PRD §A5 顺手改了一句。** 它原本写着「成员回复里 `@B` 或直接写 B 的名字就是『下一轮 B 接』」，与这条裁决直接矛盾，改成「是写给组长看的一条请求」。同一份 PRD 里自相矛盾比措辞旧更危险。

- **AD-169 的其余各条原样保留**，只有「用户点、成员点、组长点**三者同权**」这一句作废（它在 AD-169 的「落法」第三条与 `docs/ops/groups.md` §7.1b 里各出现过一次，两处都已改写）。

- **AD-154 / 信封原样保留**：房间说明与房间增量仍只含已在组时间线上公开的内容（`public_entries` 那张白名单一个字没动）；`AgentEventEnvelope` v1.1 没动；`kaus/group.changed` 的 `change` 没有新取值。

- **wire 变化：** `member_turn` 行多一个可选的 `mentions: string[]`（这一段话点到的成员 id，没点到就没有这个键），前端 `GroupMessageWire` 同步加了字段但**不渲染**。端点一条没加，没有删字段。

- **行为变化（既有端点）：** `POST /groups/{id}/broadcast` 之后，房间在第 2 轮及以后的队列只由组长那一段决定。对存量组是**收紧**：此前会被成员接力 `@` 续上的讨论，现在组长不点人就停。

- **待办：** ① 真机未验（测试单 L16 改写 + 新增 L20）；② 组长「别为了礼貌点人」那句管不管用，只有真机答得出——真机若仍是「每轮点一个人」，下一步不是再加一句约定，而是看 `roundCap` 与终止 4 那条安全阀够不够；③ 成员正文里的 `@名字` 仍未渲染成 pill（AD-169 的待办 ③，本批照旧没做）；④ 房间说明仍旧只有中文。

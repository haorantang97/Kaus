# 开发过程与追溯

以下记录保留对后续实现有用的过程和取舍，原始个人聊天、截图、登录材料及测试安装目录留在本机。

## 1. 从单一 Hermes 面板到多 Agent 宿主

早期项目围绕 Hermes profile 构建，随后拆出 Project、Backend/Driver、Binding、Conversation、SessionHost 与事件信封。Codex/Claude 桌面交互是参考，Kaus 仍保留多厂家模型、专属 Agent 能力与协作组。结构化协议接入与原生终端同时存在，不能把某一个原生协议当公共领域模型。

追溯：`docs/multi-agent-project-architecture*.md`、`docs/architecture/decisions/`、`docs/product/baseline.md`。这些早期文档有后续被更新的历史口径。

## 2. 引擎全局接入与对话交互统一

项目/profile 与引擎重复显示、模型目录过宽、可点控件未接线、侧栏信息过重先后暴露。实现改为全局引擎连接、按连接可用的模型目录、真实权限/工作模式字段和 Project 配置选择。会话引擎在开始后固定；常规模型设置可按驱动能力调整。

流式输出、图片和文件预览、复制、时间、左侧消息定位、收藏小点、悬停关闭与桌面字体分别验收。旧首页从当前主路由撤下。曾出现未发送状态与上一轮执行竞态，因此投递回执、队列/重试语义不能靠隐藏提示解决。

追溯：[全局范围审查](../global-agent-scope-audit.md)、[对话](../conversation-interaction.md)、[交互修复](../product/interaction-release-20261017.md)。

## 3. 协作组、组长与私聊隔离

把“成员已加入协作”直接投射到原私聊，会混淆身份与记录；对每个普通问题全员广播又产生重复答案。组内使用隔离执行会话，源私聊保留；独立组长做路由/综合，显式和自然语言点名按组路由规则处理。组长选择使用主平台的同一引擎目录与驱动。

资料从不适当的 Project 共享范围收束到 Group 范围。公开讨论、摘要/引用和私有上下文分别对待；不靠把所有人的完整历史无界合并实现协作。拖动加入、空组接收、菜单和组内输入防误粘贴分别修复。

追溯：[路由](../product/group-routing.md)、[组长共用驱动](../product/shared-agent-execution.md)、[组内资料](../product/group-materials.md)。

## 4. 专属技能树与原生运行隔离（10 月中旬）

用户要求同一 Project 树中并列展示通用技能和折叠的 Agent 分组。移动技能只改项目归属，来源 Agent 不变。第一次接入发现技能并进入可跳过的分配流程。

实现中发现仅改变目录或 UI 不能排除原生内置技能、动态插件和额外工作区来源。适配进一步进入原生加载/运行层，并用 selected/empty/dynamic/cold-resume、MCP A→B→空、终端往返验证。Alma/Devin 无法达到同等核心范围控制，撤出新增接入，保留存量兼容。

追溯：[隔离修复](../product/agent-isolation-remediation-20261015.md)、[技能覆盖](../product/agent-skill-support-20261016.md)、[最终适配记录](../product/agent-adapter-acceptance-20261017.md)。旧缺口须结合后续记录，不重复当作当前故障。

## 5. 本地保存、历史入口和跨 Agent 接续

讨论过独立归档和完整副本，最终产品收束为原生目录继续管理、Kaus 保存必要运行信息与引用；旧对话从项目菜单添加。原生清理由原生 Agent 负责，不做到处可见的来源缺失/档案管理界面。

跨 Agent 不是复用同一个底层 session：先生成可编辑、有限长度的公开交接正文，保留完整公开材料供按需读，用户选择附件，再创建关联的新会话。目标使用自己的 Project 配置；隐藏推理和源 Agent 专属工具不迁移。选中附件会产生实际副本，不能宣称所有存储都是零副本。

追溯：[保存规则](../product/native-archive-storage.md)、[接续协议和验收](../product/cross-agent-continuation-20261017.md)。

## 6. 设置、额度与用户工作台模块（10 月 17–18 日）

低频操作归入设置。额度优先复用已有原生登录，必要补充凭据放在对应账号旁，避免另建全局连接流程。Magpie 等公开实现用于协议比较，具体覆盖和上游限制逐项记录。

工作台最初容易被实现为平台预置的创作/自动化业务。需求明确为用户开发模块的容器：模块独立 UI/数据，Kaus 提供清单、安装、绑定、任务与 SDK；普通项目可在副本内由已有 Agent 适配，原项目不被直接改写。工作台保持模块库，常用模块拖到侧栏。

追溯：[额度](../product/account-quotas.md)、[覆盖](../product/account-quota-coverage-20261017.md)、[模块接入](../workbench-modules.md)。

## 7. 电脑操作、授权与协作控制（10 月 18–23 日）

原生能力优先，通用桌面补齐统一 CuaDriver。设置包含显式启用、自动安装、签名检查、直达系统设置、定位应用和读取验证。Peekaboo 已退出通用默认补齐；本机后来按用户要求卸载。

实际问题包括：Antigravity OAuth 建会话瞬时 TLS 错误、harness 重建后的旧消息覆盖；macOS 授权已开而旧 daemon 缓存状态；返回授权页面被重新挂载收起；中断旧 daemon 后另一个成员提前建好的 MCP 失效。修复均保留真实执行边界：特定已验证启动错误有限重试；授权以同一签名宿主回执判断；页面后台刷新不重建；每次桌面调用前核对 daemon，已发出动作不重放。

协作组使用跨进程共享控制权与持久化操作回执。等待可取消；已运行操作中断后须确认旧拥有者结束；后端重启、终端接管、远程 Gateway 后代任务均有独立生命周期处理。2026-10-23 的真实 Codex + CuaDriver 验收覆盖这些组内切换路径。

追溯：[电脑操作技术记录](../computer-use.md)、[当前覆盖](computer-use-coverage.md)、[验收](verification.md)。

## 本次发布整理

主分支与本地开发存在积累差异，更新时先核对运行目录与源码，补回缺失构建清单、图标、许可证和样式。测试安装、重复依赖目录和私有证据通过忽略规则隔离；干净候选目录重新安装依赖并检查。本目录增加持续交接入口，后续开发应随变更更新它。

跨设备检查又发现两项可复现问题：备份脚本的变量边界受中文标点影响，工作流示例锁文件带入旧环境依赖路径。两项均修复并重跑检查，顶层备份回归和独立示例检查加入 GitHub CI；桌面壳补充可重装的 macOS 依赖清单。

发布检查还移除了额度读取器中的 Google 原生 OAuth 应用常量，改为复用凭据和读取当前连接选中的原生安装。Gemini 与 Antigravity 本机安装的读取均已核对，合成测试覆盖续期、缺失/不匹配以及不执行被读取程序；参数本身不进入仓库。今后发布前同时检查工作树与待推送提交历史，不能仅依赖默认扫描规则。

首次 Linux CI 进一步暴露了 6 项测试对开发机的隐含依赖：原生权限回执测试未声明模拟 macOS，Hermes 的命令构造测试默认能找到已安装解释器。修复限于合成测试环境，显式注入平台和测试解释器；生产授权、安装探测、项目隔离与断言保持不变。新设备的协议测试应能在未安装任何真实 Agent 的环境运行。

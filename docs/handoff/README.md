# Kaus 开发交接

更新：2026-10-23。本目录供新设备、新开发者和新 Agent 接手使用。源码仓库是产品交付物，不含原生 Agent 安装、登录、私人项目库、聊天正文或本机测试截图。

## 阅读顺序

1. [当前状态](current-state.md)：产品范围、功能入口、实现与验收的区别。
2. [产品决策](product-decisions.md)：持续有效的行为与交互约定，以及为何如此设计。
3. [代码导航](architecture-map.md)：公共层、驱动、数据、界面、模块和控制权的入口。
4. [开发过程](development-history.md)：演进阶段、发现的问题、解决方式和追溯文档。
5. [电脑操作覆盖](computer-use-coverage.md)：原生与通用工具如何选择、哪些已有真实证据。
6. [换设备开发](device-setup.md)：干净安装、隔离验证、桌面运行与私人数据迁移。
7. [验收记录](verification.md) 与 [待办及边界](open-items.md)：已检查的范围、仍需登录或实战验证的部分。

## 文档如何使用

当前有效产品约定以本目录和对应专题文档为入口；实现细节回到链接的源码。`docs/product/baseline.md`、早期架构草案和日期更早的交付记录保留历史背景，不因写有“锁定”就覆盖此后的用户决定。发现当前文档与代码不符时，先复现、记录差异，再按任务范围修复或确认；不要默默改写已确认的产品方向。

测试证据分为：协议/单元测试、真实原生程序加本地模拟服务、真实账号与模型、真实 GUI/桌面验收。后一级不能由前一级推定。`output/` 中的原始报告是本机证据，公开仓库只保存去除私人数据后的结论及可重跑的测试。

每次完成实质开发后更新相应专题、当前状态、验收记录与待办。重要取舍记录动机和重审条件；功能缺口写明具体接口或验证缺口，不笼统写“上游不支持”。新 Agent 不需要读取这次开发的整段聊天才能继续。

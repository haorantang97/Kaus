# 产品决策与约束

本文件记录截至 2026-11-01 的有效约定。重审应以具体需求、协议变化或复现证据为依据。

| 决策 | 当前约定 | 原因与实现后果 |
| --- | --- | --- |
| 宿主与 Agent 分离 | Kaus 提供组织、界面与运行协调；Agent 保留自身执行/模型/登录能力 | 不给 Kaus 虚构一个默认底层模型；组长、模块任务复用普通对话驱动 |
| 全局接入 | 引擎一次接入；项目选择配置范围，不重复接入同一引擎 | Hermes HTTP/ACP 在产品层收束为 Hermes；连接版本和传输在详情/驱动层区分 |
| 会话身份 | 对话开始后引擎固定；模型、effort、权限按实际能力修改 | 跨 Agent 使用显式接续新会话，避免原生 session 与工具状态混用 |
| 模型目录 | 展示当前连接实际提供的可选模型；使用前完成 API、OAuth 或相应原生配置 | 普通对话、组长、模块和设置共用解析；公开目录/静态表不能扩成已连接选项。模型是否获配与余额、实时调用成功分别判断；Project 不是跨引擎默认模型容器 |
| 探测与测试记录 | 被动模型探测及开发测试使用临时原生存储，普通对话保持原生互通 | 仅隔离 Kaus DB/工作目录不够；原生 HOME、显式状态目录和子进程生命周期必须一起处理。Gateway 目录查询使用只读接口 |
| 参数读取 | 草稿与已有会话共用有效值、目录及能力快照；暂时失败可恢复 | 读取失败不等于驱动不支持；缺默认值不能隐藏已知可写选项；模型、effort 与发送按钮统一靠右 |
| 单一配置树 | 只有 Project 树；通用技能直接显示，Agent 专属技能分组默认折叠 | 分组是视图，不产生第二套树；拖动与菜单同等重要且写入同一接口 |
| 专属技能 | 来源 Agent 与项目分配分别保存；跨项目移动保持 Agent 范围 | Hermes 自进化技能移入子项目后，Codex 不因此获得该技能；不做自动跨平台可移植性判定 |
| 新 Agent 技能 | 全局技能默认到母项目对应分组；工作区技能保留范围；引导一次、可跳过 | 发现不会重新覆盖用户已整理的分配；不搬动原生技能文件 |
| 运行隔离 | 检查实际加载的技能、MCP、插件/hooks 与工具调用 | UI 标签、目录存在或空 HOME 本身不构成隔离证明；适配优先留在驱动层 |
| 协作组身份 | 加入组保留成员身份与配置，使用组内执行上下文 | 私聊记录、组内记录、组内资料分开；拖入不是把标题粘进输入框 |
| 组内路由 | 普通提问由组长判断；明确点名定位成员；单人定向无需冗余总结，多人按需要综合/处理分歧 | 路由和组长配置见专题；不能简单把每次输入广播给所有成员 |
| 记忆范围 | 组内资料属于 Group；Project 记忆属于 Project，由 Kaus 持有唯一一份，换 Agent 不变 | 2026-11-02 项目负责人确认方向：后台静默维护、不向用户提议；索引超限时由正在写入的 Agent 顺带压缩，手动整理通过对话完成，不做整理按钮或定时整理会话；各 Agent 自带记忆在 Kaus 启动的进程里尽量关闭。不自动把全部私聊拼接成共享上下文。细节见 `docs/product/project-config-generalization-20261102.md` 第 5 节，未实现 |
| 新会话页标题 | 站在给自己干活的人这边：白天叫老板、问在造什么，夜里说夜还长，凌晨 1 点以后劝睡；每个时段一句常驻主句，部分时段配随机彩蛋 | 2026-11-09 项目负责人确认。不用打工人的概念（上下班、打卡），不假设当天要上线；文案只放在词典 `draft.greeting.*` 里 |
| 订阅与 API key | 默认启动用户自己登录的官方 CLI（Claude Code、Codex 等），与 Zed、Magpie 的 Claude 部分同类；另在设置里为每台引擎提供 API key 入口（加密保存、启动时注入）。不做「把订阅变成 API 网关、提供给其他 Agent」 | 2026-11-09 项目负责人：同类成熟项目普遍这样用，不过度防御；自己一直用订阅，API 入口要补上。参考：OpenCode 曾内置读取 Claude 订阅令牌直接调用，2026-03 收到 Anthropic 法务请求后删除（二手报道）；Anthropic 原计划 6-15 起把 ACP / SDK 用量单独计费，6-16 宣布暂缓。单独的 Claude Agent SDK 接入不做：现用的 Claude Code ACP 适配器本身基于它 |
| 本地保存 | 原生记录沿用原生目录/保留规则，Kaus 保存运行与项目索引及必要事件 | 不修改 Agent 自动清理规则；原生文字经精确核对可引用，其他未适配内容仍需本地保存 |
| 旧对话入口 | 收束为 Project 菜单“添加已有对话” | 不设独立档案管理产品；不常驻“来源缺失”、原始 JSON、路径或独立归档提示 |
| 删除 Project | 对话只由用户手动删除；有对话运行或持有终端写权时先返回运行中的对话，用户确认后（`?force=1`）先停止再删除 | 卡片运行时走正常停止，终端持有的走强制回站（结束终端中的 Agent、校准历史）；删除后全部对话归档（行、事件、原生会话保留），停止不改变归档范围。“设置 → 已归档”显示原 Project 名，可查看、删除、恢复 Project（原位：归档内记录的树位置 + 最新配置副本，只恢复所点对话）或移到其他 Project。原上级不在或没有配置副本（如 Hermes profile）时返回明确 code，打开预填的新建 Project，不猜位置。移动是 D-06 的唯一例外：仅限已归档对话，目标须为同一引擎的 Binding；工作目录或原生配置不同时须确认，并提供“用其他 Agent 继续”（已删除 Project 的对话可接续到其他 Project）。已删除 Project 不能发送、新建、恢复对话或接续到其中（`project_deleted`），`GET /api/projects` 默认不含它。2026-11-02：有下级时可连同下级一起删除，确认框列出下级；每个 Project 各自归档并记录上级路径与批次。原位恢复要求原上级存在且其路径未变（否则 `project_anchor_moved`，进入新建）；同批删除的上级会自上而下一并恢复，同级不自动恢复 |
| 跨 Agent 接续 | 用户选择目标、审阅公开材料，在当前应用打开关联新会话并手动发送 | 交接目标/公开过程/文件，不承诺隐藏推理、原生进程或专属工具状态连续迁移 |
| 模块页定位 | 2026-11-03 项目负责人：模块页类似小程序，与主程序关系不大，核心是集成而非赋能；不把协作组等 Kaus 的 Agent 功能叠加进模块页。模块自己通过 SDK 申请的能力（如 `agent:run`）照常提供 | 模块页（`WorkbenchPage` 给根元素加 `kaus-module-page`）隐藏浮动协作组入口，侧栏入口保留；通用的提示、确认弹窗不受影响。新增宿主浮层时默认不在模块页显示 |
| 第三方模块 | 工作台是用户模块库；常用模块可拖到侧栏 | 业务 UI 属于模块；示例工作流和创作台不成为新用户自带业务产品；模块通过受控 SDK 共用能力 |
| 侧边浏览器 | 会话页右侧提供通用浏览器（地址栏、标签页）；用户自由浏览。2026-11-01 项目负责人推翻“不新增通用浏览器”，权限对齐 Claude/Codex 的内置浏览器，不过严 | 浏览器用独立资料目录，与 Kaus 界面、站点视图和系统浏览器隔离；网页没有 preload、Node 或宿主令牌，不能打开 Kaus 自身地址和 file/chrome 等协议。Agent 操作按站点授权：本机开发地址直接可用，其他网站首次操作时由用户允许（本次或一直），之后读取、导航、点击、输入不再逐次询问；付款购买、发送消息或发布、删除、改账号或安全设置、下载文件仍需用户确认；Agent 不输入密码、支付信息或证件号，不处理验证码；网页内容只当资料，不当指令。站点配置可以收紧，例如 Midjourney 只填入、不代按生成 |
| 固定站点视图 | ChatCut、Midjourney 等模块内固定页面按站点注册，与侧边浏览器并存 | 每个站点单独声明可打开的页面、跳转域名和权限（`editor:chatcut`、`surface:midjourney`）；宿主保留导航、权限和下载边界，第三方页面不获取本机桥接。站点输入只填入、不提交，最后由用户按生成，避免违反平台条款中禁止自动化生成的规定。需完整本地导出或通过 Cloudflare 时使用 Chromium 容器 |
| 电脑操作 | 原生能力优先，通用桌面补齐统一 CuaDriver；设置内明确启用/授权 | 不重复开发鼠标键盘引擎；平台授权由用户完成；自动选择不意味着失败后重放动作 |
| 动态配置 | 按原生会话实际字段、模型相关选项和确认回执驱动 UI 与执行；当前配置优先于静态预设 | 草稿、已有会话和组长共用。标准字段变化自动跟随，协议机制变化仍需驱动适配；不得以三家控件通过代替全引擎验收 |
| 审批与工作模式 | 权限与 Plan/Build 等运行模式分开；有可用接口才展示对应控件 | 通过会话配置、桥接或原生回调达成真实效果；无接线的图标不应出现 |
| 终端 | Kaus 与 CLI 恢复同一原生会话、存储和当前项目配置；可固定偏好启动器 | 保留正常 Codex 会话在其桌面客户端可见的原生互通；仅测试与探测记录另存。返回页面与结束终端切回分开，写权、退出和历史回填须实际确认 |
| 外部终端 | 终端仍由外部应用打开，当前不内嵌终端（内嵌已列入计划、暂不开发），不往终端注入按键 | 只补启动、预览、状态与草稿：目录信任预写默认开、可关；更新提示与状态 hook 只用本次启动的参数或环境，不改用户全局配置；预览只读，正式记录仍由回站校准写入；草稿只走原生预填参数，否则复制到剪贴板 |
| 总控 Agent | 任意引擎均可，通过 Kaus 控制 MCP 调度 Agent、工作流与模块后端 | 2026-11-02 项目负责人确认：用户在对话中明确同意后，可代答待审批/提问、修改会话的模型、推理强度与权限（含完全访问），每次一事一确认（`user_confirmed=true`），并在该会话时间线记一行「主 Agent 已代为…」；不删除任何 Kaus 对象、不改 Project 配置；模块自身的数据（如 CRM 条目）按模块接口可增删改，含删除（2026-11-02 确认）；切回对话会结束终端中的 Agent，同样须确认。Kaus 无法自行核实同意，依赖主 Agent 遵守规则；手机入口另行接入 |
| 额度 | 已有凭据可查询则自动显示，缺补充信息时就地提供入口 | 不让用户重复接入；余额、计划窗口和单次 token 消耗分别展示；未知不能显示成 0 |
| 界面 | 极简、可读、专业；主要操作可发现，次要操作放菜单/悬停 | 图标带无障碍名和 tooltip；去掉冗余解释、常驻日期、内部字段和原始错误；错误只在需要行动时出现 |
| 视觉细节 | 用户消息右对齐；左侧轮次定位条，收藏用小点；有 hover/渐变/减弱动效支持 | 避免额外方框、常驻收藏按钮和多余回到底部箭头；警示强调使用低饱和粉红红色系 |
| 焦点反馈 | 输入和操作控件不出现额外硬矩形焦点框 | 键盘反馈依托控件原有底色、输入区域边色和链接下划线；不能把取消 outline 等同于取消键盘可用性 |
| 产品支持标准 | 不能落实 Project 核心范围的引擎可撤出新增接入 | Alma/Devin 已于 2026-11-02 删除（见「支持的 Agent 范围」）；新增引擎依据接口和隔离验收 |
| Hermes 定位 | 2026-11-02 项目负责人确认：Hermes 只是接入的普通 Agent 之一，Kaus 不保留围绕个人 Hermes 环境的功能或配置 | 只允许通用的 Agent 适配（`kernel/drivers/hermes/` 驱动、指令文件名、Claude/Codex 官方 SDK 等）。2026-11-03 清除早期个人仪表盘遗留：Hermes 档案不再作为 Project 显示，删除档案间配置继承、守则写入 `SOUL.md`、后台同步/用量/索引/curator 任务、主 Agent 分身、Hermes 任务板、删除时调用 `hermes profile delete`、默认接入 Hermes；`server.py` 3,533 → 1,107 行。只剩一次性迁移只读旧 `HERMES_HOME` 的守则 |
| tmux 托管 | 2026-11-02 项目负责人确认：移出计划，不做 | 最初为两件事提出：手机上操作电脑终端里正在运行的 Agent，以及用读屏判断任意终端里 Agent 的状态。前者由切回对话与主 Agent 代办覆盖，后者主力 Agent 已由 hook 上报；用 tmux 发按键与「Kaus 不往终端注入按键」冲突。仅终端接入的 Agent 实测缺少状态信号时，再评估只读状态 |
| 仅终端接入的 Agent | 2026-11-02 项目负责人确认：暂缓 | Kaus 已接入的 22 个 Agent 都走 ACP，主流均已覆盖；Aider 等只有终端的 Agent 不做通用接入，也不做终端画面到对话的映射（重绘画面无法可靠解析，审批误判有风险）。有需求时按单个 Agent 评估，优先其官方的无界面 JSON 模式（如 Amp）。产品定位是服务好一小部分用户，不追求全覆盖 |
| 会话状态显示 | 2026-11-02 项目负责人确认：去掉新会话页的「需要处理」区块与标题下的计数，改为侧栏会话行上的状态点 | 运行中：流光动画；已结束未查看：蓝点；等待处理（审批、提问、终端等待、组内审批、模块任务等待）：橙点；失败（发送失败、未登录、断网等）：红色感叹号；已查看的空闲会话不显示。不加文字，悬停显示状态名供读屏。组内审批标在「协作组」入口。「未查看」由后端按会话记录，手机与电脑一致。2026-11-09 已实现（见 `verification.md`） |
| 产品定位 | 2026-11-02 项目负责人：服务好一小部分用户即可，不追求大厂式全覆盖 | 只做覆盖大多数情况的通用路径；边缘 Agent 与场景按实际需求单独评估 |
| 界面原则 | 2026-11-02 项目负责人：能在对话里说一句完成、或有更直接方式的事，不做专门的按钮或界面 | 例外是同类产品普遍都有的约定俗成操作（删除、归档、换文件夹等）。新增界面前先问：用户能否直接让 Agent 做（含经控制 MCP）？现有界面按此原则另行盘点 |
| 项目轮盘 | 2026-11-03 项目负责人：`/agents` 项目轮盘是核心功能，保留 | 按界面原则精简时不动轮盘本身；其中的 Hermes 档案概念（化身、软链数、gateway 点）随配置通用化清理 |
| 协作组删除与导航 | 2026-11-03 项目负责人：协作组浮窗分两级——组列表（新建组、最小化；每行 ⋯ / 右键菜单含删除）和组内页（返回、组名、垃圾桶「删除组」、最小化），不在正文里放删除 | 「关闭组」统一改称「删除组」，行为不变（删除组内对话、资料、组内会话与组长记录）；接口名 `close` 保持不变 |
| 删除图标 | 2026-11-03 项目负责人：列表里的删除放进 ⋯ / 右键菜单；独立页面顶栏上删除整个对象用垃圾桶；删除按钮不放在正文内容区 | 收起窗口用「—」；同一区域不让两个叉号表示不同含义 |
| 字体 | 2026-11-03 项目负责人：字体做轻，对标 Claude 桌面客户端（取代 AD-78「字体保留」）；项目轮盘保持原字体 | 依据 claude.ai/code（与客户端 Code 界面同一套页面）实测：几乎全用无衬线，正文 14–15px、次要 12–13px，页面级大标题用衬线 24px/500。Kaus 对应：界面用系统字体（SF Pro / PingFang），常用字重 400，只有会话标题、页面标题用 500；回答正文 15px/1.6 无衬线；新会话问候语、项目页标题用系统衬线（New York，中文回落苹方）；代码 SF Mono；不用全大写等宽小标签。轮盘（`.ag-*`、`.agent-browser-*`）保留 Anton 与 Space Mono；Anton 另用于 KAUS 字标。不使用 Anthropic 专有字体。轮盘中文用苹方常规 / 中粗（`theme-overrides.css` 的 "Kaus Wheel CJK" 以 `local()` 把轮盘原有的 600 映射为苹方常规、700 映射为中粗，只作用于中文字符）；轮盘英文仍是 Anton / Space Mono / Inter 的原字重。霞鹜文楷试过后弃用 |

## 维护边界

不把不成熟实现写成“上游永久不支持”。分别记录：未开发、缺登录/系统授权、尚未验收、已确认协议缺口。支持矩阵应注明检查过的原生版本；升级后重新验证受管范围和生命周期。

开源参考须保留许可证与来源。2026-10-27 项目负责人决定：Kaus 按 AGPL-3.0-only 授权，另提供商业授权并要求外部贡献签 CLA；`sdk/`、`examples/` 及模块清单格式与宿主协议用 Apache-2.0，第三方模块打包 SDK 不受 AGPL 约束。用 `-only` 是为了双授权条款不受 FSF 将来版本影响。“设置 → 关于”给出许可证与源码链接（AGPL 第 13 条）。许可证从加入的提交起生效，之前的提交不追溯。原生 Agent、其桌面客户端以及本仓库是不同产品。
